# 全站財務連動盤點與修正

## 範圍與原則（2026-09-03）

使用者授權完成訂單歸屬功能更新，並盤點目前 Django 全站財務流程。Odoo 是封存系統，不改寫其公式。本輪不重新定義收入認列、不批次重算歷史已付款／已領牌金額。

一次修改必須同步受影響的應收、收款狀態、試算、成本、淨利與報表，失敗回滾；訂單快照、人工覆寫與已結算資料須保留。盤點覆蓋各入口及既有公式，不代表所有歷史金額皆已核對正確。

## 入口與依賴清單

| 範圍 | 實際入口／來源 | 下游及本次結果 |
| --- | --- | --- |
| 車價、訂金、加購、工資、其他費用、舊車折抵 | `order_create/edit`、`calculate_balance` | 尾款→應收紀錄；人工尾款保留原因。金額異動會重算應收，保留原實收與證明；單純開頁不回填歷史應收。 |
| 折扣 | `order_discount_request/decide` | 沿用核准後才減應收；重算尾款及收清狀態。是否同步減營收須確認。 |
| 分期方案與預估撥款 | `apply_order_installment_snapshot` | 保留訂單日快照；僅方案相關輸入變更時更新，修改備註不重套新方案。 |
| 領牌稅金、強制險、選號 | `registration_save/complete`、`operations_sync` | 收支配對同步，人工覆寫受保護；完成領牌保留快照。 |
| 車輛成本、實銷獎勵、促銷及息補 | `settlement_cost`、`incentive_rule`、主檔修改 | 未領牌訂單重新匹配有效費率，已領牌或已鎖定不重套；整單編輯也補齊重算。 |
| 基礎傭金及車行加減額 | `dealer_commission` | 原銷售車行費率不因歸屬而換套；修正再次套用覆寫鎖定快照的缺口。 |
| 台數獎金及歸屬 | 明細、整單編輯、結算／更正 | 依原領牌期間計數；阻擋加入已結算期間或改動已結算依據；分攤、成本與淨利同一交易更新，拒絕負數／非整數。 |
| 收款、分期及平台對帳 | 交付收款、營運表單、統一對帳、`PaymentRecord` | 共用實際撥款、刷卡費連動；逐筆判斷收清，溢收不抵另一筆未收款；新確認保存撤回快照。 |
| 取消收款確認／刪除 | `PaymentRecord` | 新連動恢復確認前人工金額或本單預估；不由舊資料猜測原值。 |
| 人工營運金額 | `OrderOperationsForm` | 保留人工保護欄位；不開放修改傭金基礎、鎖定時間等內部快照；收款管理中的實際撥款須改原收款紀錄。版本衝突拒絕覆蓋。 |
| 取消／退款 | `request_cancellation/complete_refund` | 現行只支援全額退訂金；取消單不列一般營運／首頁淨利，收款與退款各自留存。 |
| 補助與履約 | `SubsidyItem`、營運補助欄位 | 申請追蹤不是本店收入，不把代客補助重複加入淨利。 |
| 淨利、首頁、總表、匯出 | `OrderOperationsProfile.net_profit`、`dashboard_metrics`、`operations_report` | 共用保存收支及淨利公式；首頁／總表排除取消單，成本未備齊另行辨識；不改認列時點。 |
| 歷史匯入與修訂 | `legacy_import`、management commands | 保存歷史快照；bulk 路徑不適用一般重算。本輪唯讀檢查，不重匯、不改歷史值。 |
| Django 管理後台 | `sales/admin.py` | 訂單、營運、結算與分攤改為唯讀，避免繞過正式頁面稽核、連動與驗證；主檔仍可維護。 |

## 待確認的營運規則：不猜改

1. 本店人員 `staff_commission` 目前只有主檔金額，尚無逐單列支／給付紀錄。須確認是否每台固定、認列時間、退車撤回，以及是否可與車行傭金並存。
2. 台數獎金目前是「車行＋品牌＋期間＋台數門檻」。能源別／指定車型條件，以及多規則同時命中應疊加或擇一，尚未定義。
3. 折扣、加購、舊車折抵會影響應收，但淨利依實際撥款＋營運收支計算。須確認應自動列入哪個收支欄位，避免與人工金額重複認列。
4. 取消只限定退訂金。已收尾款、分期／平台入帳、刷卡費及溢收的退款順序、金額與沖帳須另訂規則；本輪列出待核對資料。
5. 人工傭金總額是否已含台數獎金不明時，不自行拆分；更正分攤後人工總額仍須核對。
6. 舊對帳確認沒有確認前快照：取消確認不能回推原人工金額，保留舊值並列入檢查，不能宣稱歷史帳都已清理。

## 唯讀資料盤點

```sh
python manage.py audit_financial_consistency --sample-limit 30
```

全數掃描缺少營運資料、尾款公式／原因、逐筆收清、刷卡費、已確認撥款、撤回快照、已領牌成本、傭金快照＋獎金、取消收款及結算分攤；最多列 30 個例子。只列訂單編號及差異，不輸出姓名、證件或帳號。

Migration `0112` 只新增空 JSON，不回填舊金額。檢查包含「需核對」項目，不代表全是錯帳，不能直接批次修改。

另檢查已領牌且有成本但實際撥款為零的訂單；歷史收款價依 `029/03-import-mapping.md` 獨立保存，未確認其與實際撥款的對應前不得自動轉列收入。歷史收款確認標記與逐筆金額須分別核對，不能只清除標記或補造收款。正式資料盤點結果及待補明細保存於本機交付報告，不將正式訂單資料提交至 Git。
