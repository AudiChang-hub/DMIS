# 原廠車型比對（A 方案，第一階段）

批准：使用者 2026-09-30 選擇 A 方案（正式站管理畫面），同意分兩階段發布、僅限最高權限使用；原廠已同意使用官網圖片。

## 問題

車型圖片與車色資料需要從 SYM、SUZUKI 官網手動整理；改款時（名稱不變、圖片與價格不同）容易漏看。功能須可交接給其他人在正式站操作。

## 範圍與接受條件（1.23.0）

- 選車展示管理 → 原廠車型比對（`official_catalog`，ROOT_ONLY）。按「檢查官網」排入 `imports` 背景佇列，逐頁讀取官網；
  同品牌 30 分鐘內只允許一個進行中的檢查，逾時的舊檢查標示失敗。
- 來源只限 `tw.sym-global.com` 與 `www.suzukimotor.com.tw` 的 https 網址，轉址到其他網域即停止；頁面 3 MB、圖片 8 MB 上限；
  每頁間隔 0.5 秒。官網以 HTML 註解隱藏的車款、車色與售價不採用。
- SYM 一頁的多個版本（例如 ABS／標準）各為一筆官網車型；車色數與圖片數不一致時該頁不採用並記錄錯誤。
- 官網車型與系統車型的對應必須由人確認（建議只依名稱與排氣量相近推測）；一個系統車型只能對應一筆官網車型。
- 分類：待對應、有變動（對應後官網內容雜湊與上次確認不同）、可補圖、已對應、已忽略（官網內容再變動時重新列出）。
  列表讀取成功但某車型不再出現時標示「官網已下架」；該頁讀取失敗時不下結論。
- 可補圖只列出啟用、無圖片、且色號或色名能雙向唯一對應官網的車色；補圖時重新計算對應、重新下載並驗證 JPEG／PNG／WebP，
  鎖定車色列後仍無圖片才寫入，寫入稽核紀錄。
- 售價只顯示官網與系統目前建議售價的差異，不寫入售價版本。

## 不做（安全邊界）

- 不修改既有車型的廠牌、名稱、型號、年份、型式、排氣量、動力類型、領牌級別、啟用狀態、車色名稱、車款上架狀態或任何售價版本；
  既有訂單的列印、領牌試算、報表與搜尋不受影響。
- 不覆蓋既有圖片；更換圖片仍使用選車展示管理。

## 第二階段（1.24.0）

- 待對應可「從官網建立車型」、有變動可「改款：建立新年式」：開啟現有新增機種／年式表單（`vehicle_model_create?official=<id>[&base=<年式>]`），
  預填名稱、年份（官網年式，否則原年式＋1）、排氣量（油車）、馬達 kW（電動）、車色；新年式另帶既有機種、型式與原廠型號。型號與型式由人確認。
- 只有 admin 可使用官網帶入；新年式的 base 必須是該官網車型目前對應的年式，未對應的官網車型不能帶 base。
- 儲存時強制停用（不建立展示上架），同一交易內把對應移到新車型並記錄稽核；舊年式資料、車色、圖片與訂單不變。
  送出時若官網車型的對應已被他人變更，整筆不儲存並提示重新操作。

## 回復

migration 0157 只新增 `OfficialCatalogCheck`、`OfficialCatalogModel` 兩張表，不改既有表。回復程式到 1.22.3 後可保留兩張表或 migrate 回 0156；
已補上的車色圖片可在選車展示管理逐色移除（稽核紀錄列出補圖的車色）。
1.24.0 無 migration；回復到 1.23.x 即可，從官網建立的停用車型可在機種與售價刪除（未被使用時）。
