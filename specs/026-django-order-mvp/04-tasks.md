## UI 版面驗收（每次 UI 修改皆必須執行）

- [ ] 桌機 `1440×900`：確認主要頁面無元素重疊、裁切或不合理留白
- [ ] 平板 `820×1180`：確認雙欄能正確降欄，表單與按鈕不超出容器
- [ ] 手機 `390×844`：確認無水平溢出，底部操作列不遮住導覽列
- [ ] 檢查首頁、訂單清單、庫存、新增／編輯訂單及訂單所有工作頁籤
- [ ] 在網址加入 `?ui_audit=1`，確認瀏覽器的 `data-ui-layout-issues="0"`
- [ ] 橫向滑動元件必須明確設置可捲動容器，不得造成整頁水平捲動

## UI／UX 導覽驗收（每次新增或修改頁面皆必須執行）

- [ ] 除首頁等最上層頁面外，每個畫面都要提供清楚、可預期的返回入口
- [ ] 返回入口放在頁面內容最上方，並盡可能回到使用者上次看到的清單、篩選與捲動位置
- [ ] 若沒有站內瀏覽紀錄，返回入口必須有可用的固定目的地，不得失效
- [ ] 表單有未儲存資料時，離開前必須提醒；已有自動草稿時不得造成資料遺失
- [ ] 手機底部導覽僅切換最上層區域；當前區域必須有文字與顏色狀態，不得只靠圖示
- [ ] 所有可操作元件的觸控範圍至少 `44×44px`，並具備清楚的鍵盤焦點樣式
- [ ] UI 改版不得移除或搬離已確認的關鍵功能：證件對照預覽、照片刪除、動態項目刪除及必要操作按鈕
