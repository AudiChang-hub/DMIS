# 人員畫面權限實作與驗收

## 操作

admin → 資料維護區 → 帳號與權限 → 人員右側「畫面權限」，或頁首「權限總覽」。
勾選畫面／報表的查看、操作、匯出後，先「預覽變更」，再「確認並套用」。
複製另一位人員及歷程還原都只產生預覽，不會直接變更，也不複製管理者身分。

舊人員第一次設定前標示「沿用舊制」，維持上線前的資格；確認後才採白名單。
系統帳號建立頁新增的人員先採空白白名單。CLI 建立等維運流程仍應由 admin 補上設定。
未開放戰情首頁時登入後導向「我的可用功能」。無業務授權仍可變更密碼、登出及使用個人外觀。

## 實作邊界

- `sales/access/registry.py` 明列畫面、路由、共用 API、來源檔及主檔啟停映射；alias 使用同一規則。
- 共用流程分組：訂單及草稿；訂單作業及文件；通路與人員（合作車行、平台、本店人員、通路類別、節禮）；機種及售價／分期方案。
- 作業頁可由已開放的訂單或營運總表進入，獨立授權不隱含開放原訂單維護。
- 混合列表 GET 只讀、POST 操作；新增／編輯表單 GET 同樣要求操作。列印範本開放即包含其原有範例訂單資訊。
- 畫面權限不是列級或欄位遮罩；首頁統計、客戶歷史摘要、通路清單等依畫面原有內容提供。尚未加入的資料範圍限制不可宣稱已支援。
- 報表既有 audience 與人口／原始備註限制為上限；新發布報表對白名單人員預設不開放。
- 直接網址、API、POST、下鑽、系統匯出均於後端驗權；選單、手機捷徑與主要列表／報表連結於伺服端過濾。獨立原始文件依所屬畫面檢查。
- admin 固定最高權限，其他管理者不得接管；已設定白名單的其他 superuser 禁用 Django admin 繞路。
- 權限請求內快取、不跨請求；私人頁 no-store。已下載或已顯示內容不能遠端撤回，瀏覽器本身截圖／列印不在控制範圍。
- 預覽簽章綁定操作者、人員、版本，30 分鐘有效；CSRF、交易、user 列鎖及版本比對防止覆寫。
- 歷程保留前後快照；還原仍須符合當下資格，不能還原成舊制無限制模式。

## 遷移及回復

Migration 0126 僅新增四張權限表，沒有變更既有人員、帳號角色或業務資料。
先完成正式資料庫／媒體備份再部署。若需回退程式，先通知管理者舊版不會執行新白名單，
不得將直接回退宣稱為安全撤回；宜優先保留版本並修正。權限調整錯誤可由 admin 歷程還原再確認。

## 驗證狀態

本機權限與相容性重點測試 26 項通過（其中 PostgreSQL 列鎖 1 項在 SQLite 跳過）；既有前端測試 51 項通過。
真實 Chrome 已檢查桌機、390px 手機、820px 平板、鍵盤勾選、連動取消、變更篩選、預覽與返回；未在正式人員上套用測試權限。
首輪完整 979 項測試抓到 11 個舊制 404／403 相容性差異，已修正並重測相關案例；另補 3 項防呆測試。完整重跑與 PostgreSQL 由提交後 CI 執行，部署須待通過。
自動測試涵蓋路由覆蓋、拒絕 GET／POST、
查看與操作／匯出分離、敏感資格上限、跨人員 token／歷程、立即撤權、root 保護、
CSRF、新帳號預設及 PostgreSQL 首次設定併發。
