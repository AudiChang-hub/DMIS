# 開發與驗證（按需）

安裝與啟動見 [README](../../README.md)。本檔只管測試，不重複商業規則。
可用測試清單以 [.github/workflows/ci.yml](../../.github/workflows/ci.yml) 為準；不代表每項任務都要在本機跑整份清單。

## 風險分級與工作上限

先依實際行為與影響範圍分級，再選驗證；不能只看檔名或修改行數。目標是同等品質下減少無關工作，不是省略必要規則或掩蓋未驗證項目。

| 等級 | 修改範圍 | 必要驗證 |
| --- | --- | --- |
| L0 文件 | 開發政策、說明文件；不影響 runtime | 文件連結、相關政策檢查；不啟動應用、DB、瀏覽器或容器，不升應用版、不部署 |
| L1 呈現 | 純文案、單頁局部樣式，無邏輯／資料變更 | 受影響模板／文案測試；樣式另驗受影響頁面與尺寸／主題，不跑無關業務套件 |
| L2 局部功能 | 表單、互動、查詢或共用 UI 行為 | 相關單元／整合測試與實際流程；共用 UI 選代表頁面驗證 |
| L3 高風險 | 權限、安全、金額公式、匯入核心、schema、刪除、鎖定、共用基礎設施 | 依影響執行跨模組回歸、必要的 PostgreSQL／安全／建置檢查；無法界定影響或廣泛改動時跑完整套件，遵守重大修改核准規則 |

- 「只改文字」若改變金融／法律意義、權限承諾或資料口徑，須先釐清；隱藏按鈕或改查詢條件不是純樣式。全域 CSS、導覽與共用模板至少按 L2 驗證。
- 起手只讀必要指令、相關程式及測試。不要為文案讀全部商業規則、archive、migration、logs，或啟動無關 MCP／Web／子代理。
- 先跑便宜且直接相關的檢查，通過後才跑必要的昂貴檢查。不因「以防萬一」擴成全站重構、順手修舊問題或建立大量規格文件。
- 預計單項驗證超過 5 分鐘時，先簡述它覆蓋的風險、是否為強制門檻、為何相關檢查不足；不是要求使用者反覆批准原已授權工作。L0／L1 工作若持續擴大，先重判範圍，必要時提報新增工作，不能默默做下去。
- 同一提交、相同環境且輸入未變的有效測試結果可沿用並註明來源。不在本機與 CI 重複跑同一完整套件；修正後重跑受影響部分，若必需重新跑強制門檻則如實說明。舊提交結果不能冒充新提交已通過。
- 版號／發布歷程調整優先跑發布檢查與版本可見性測試；不因修改版本說明而自動加跑財務套件。
- 等待 CI 使用有界等待與合理輪詢，避免重複下載同一份完整日誌；必要進度回報保持簡短，不反覆展開相同調查。
- 結案列出修改、實際驗證及未驗證／未部署項目。小修不附無關長篇分析、額外方案或未執行的承諾。

### 現行 CI 限制

2026-09-22 核對：CI 對 main push／PR 仍固定跑全站 SQLite、多組 PostgreSQL 及映像建置，尚未實作風險分流。本政策不會自動縮短這些工作，也不得略過強制檢查或把未跑當通過。需要發布的小修應事先說明此等待成本；不額外在本機全跑。純政策工作不自動建立 PR／push 觸發整套流程。CI 分流屬另項流程修改，須另行核准、實作及驗證。

## 最低驗證

只做初始定位：`python tools/context_lookup.py catalog` 或 `python tools/context_lookup.py importer`。
它只讀三個指定檔案、輸出命中規則與函式，沒有 DB／網路操作；路由過時或輸出過大會報錯，不退回全站掃描。

依分級選擇，不把下列命令一律套用到所有修改：

```powershell
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test <受影響測試> --noinput
```

- `check` 用於 Django 程式／設定異動；migration 檢查用於模型／schema／migration 異動。純文案／局部 CSS 不必在本機執行這兩項。
- 合併／正式部署前完成分級所需驗證及現行強制 CI 門檻，不額外要求每次在本機跑完整 Django 測試。財務、佣金、台數歸屬、結算、併發與鎖定異動須保留相關 PostgreSQL 測試，不能只用 SQLite。
- 前端測試依受影響 `tests/frontend/*.test.cjs` 執行；完整清單看 CI，不維護另一份易失效列表。
- 依賴變更跑 `python -m pip_audit -r requirements-django.txt`。
- 設定／容器變更跑 `python manage.py check --deploy`、建置 `Dockerfile.django`、檢查 runtime allowlist 與非 root 使用者。只用測試專用 secret 與 DB，CI 不能使用正式密碼。
- migration 檢查使用 `--check --dry-run`；不因為跑測試順便對正式 DB migrate。
- 財務稽核 `python manage.py audit_financial_consistency --sample-limit 30` 是唯讀；仍須確認目標與授權。
- 純文件／AI 設定修改跑 `python -m unittest discover -s tests/context -v` 與 `python scripts/check_release.py`，不需啟動應用或升應用版號。

## UI 驗收

僅驗受影響頁面與相關互動，不每次全站巡檢。純文字改名檢查文案及無截斷；排版修改檢查桌機 1440×900、平板 820×1180、手機 390×844；色彩修改檢查受影響主題與對比。網址加 `?ui_audit=1` 時檢查根元素 `data-ui-layout-issues=0`。
按影響選查鍵盤焦點、選單、彈窗、固定操作列、拖拉替代操作與放大；驗收項目見 [026 tasks](../../specs/026-django-order-mvp/04-tasks.md)。
模板字串與 CSS 靜態測試不等於瀏覽器／實體手機、相機、分享、印表機驗收。

## 規格與發布

runtime／部署行為變更更新相符 specs，保留舊資料相容性、交易、鎖定、唯一鍵、FK、可重跑及回復策略。
升版、不可變更的已發布歷程與 CI 後標籤依 [RELEASE_POLICY](../RELEASE_POLICY.md)。
如實列出未跑、skip 與失敗，不能把「準備執行」寫成通過。代管安全掃描是否啟用需即時查證，不能以本機稽核替代。
