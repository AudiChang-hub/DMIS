# 06 — 車行管理模組維護規範

> **狀態**：長期有效（Frozen Module）
> **適用範圍**：`addons/dms_core/` 全體檔案
> **負責人**：專案負責人

---

## 1. 凍結聲明

`dms_core` 模組已完成所有既定功能，視為**凍結模組（Frozen Module）**。
在未獲得專案負責人書面核准前，任何人不得對本模組進行以下操作：

| 禁止操作 | 涵蓋內容 |
|----------|----------|
| 直接修改 | 模型欄位、視圖、控制器、安全設定、資料檔案 |
| 重構 | 邏輯重整、命名變更、方法合併/拆分 |
| 刪減 | 欄位刪除、菜單移除、ACL 規則縮減 |
| 覆寫核心邏輯 | 在其他模組中以 `_inherit` 蓋掉既有行為（需另行評估） |

---

## 2. 允許的操作方式

若確有正式需求（需有對應 specs 文件），可採下列**非侵入式**方式實作：

1. **繼承擴充**：另建獨立模組，以 `_inherit = 'dms.dealer'` 新增欄位或覆寫方法。
2. **獨立模組**：新功能封裝於新模組，`depends` 中加入 `dms_core`，不修改原始檔。
3. **視圖繼承**：以 `inherit_id` 在新模組的 XML 中擴充視圖，不直接編輯 `dms_core/views/`。

---

## 3. 安全與權限

- `addons/dms_core/security/` 下的 ACL 與 Record Rules 為**唯讀**，禁止隨意變更。
- 若需新增角色或調整權限：
  1. 先在 `specs/001-dms-core/04-tasks.md` 提出任務
  2. 在測試環境驗證無衝突
  3. 取得核准後才可合併

---

## 4. 向下相容要求

任何涉及資料結構的變更（欄位新增/刪除/改型別）必須：

- 附帶 `migrations/` 升級腳本
- 在 `specs/` 中說明遷移策略
- 在正式合併前於測試資料庫（`dmis_dev`）完整驗證

---

## 5. 測試與驗證

改動前後必須執行並通過：

```bash
make up
make smoke
docker compose ps
# 以及
docker compose run --rm odoo odoo -d dmis_dev --test-enable \
  --test-tags dms_core --stop-after-init
```
