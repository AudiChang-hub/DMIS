# 032 產品體驗、安全與使用說明強化｜Spec

## 1. 任務導向幫助中心

- 登入後可從桌機與手機任何頁面進入「使用說明」。
- 入口需帶入目前頁面對應章節，且避免讓使用者遺失尚未完成的輸入。
- 說明以「我要完成什麼」分組，不以程式模組或資料表分組。
- 每個主題至少包含：使用時機、操作步驟、完成結果、例子、例外處理。
- 提供關鍵字搜尋、列印／另存 PDF、名詞白話解釋。

## 2. 表單防呆與回復

- 必填未完成時，只顯示一份錯誤摘要，而不是多個重複提示。
- 錯誤摘要可點擊並移到對應欄位。
- 欄位說明與錯誤需透過 `aria-describedby` 提供輔助科技辨識。
- 送出期間顯示處理中並阻止重複送出，但不得遺失送出按鈕的 `name/value`。
- 手機離線時顯示不遮擋操作的持續提示；不得誤稱尚未實作的離線佇列已完成同步。

## 3. 錯誤與支援線索

- 400、403、404、500 均使用 End User 可理解的繁體中文頁面。
- 每個請求產生不含個資的查修編號，500 頁顯示該編號。
- 回應帶 `X-Request-ID`，伺服器記錄同一編號以便比對。

## 4. UI/UX 基線

- 正文最小 16px，手機操作區至少 44×44px。
- 導覽名稱與畫面按鈕使用相同用語。
- 不以顏色作為唯一狀態提示。
- 主要頁面保留一致的返回、頁面標題、主要操作與情境說明入口。
- 所有可新增資料列必須提供可理解的移除操作與必要確認。

## 5. 安全基線

- 正式環境禁止預設密鑰、關閉 Debug、採安全 Cookie 與 HTTPS。
- 私密文件需登入、禁止快取，避免把個資寫入一般 log 或查修編號。
- 重要異動保留操作人、時間與變更原因。
- 帳號不得共用；角色權限、MFA 與登入限速列為擴大使用前的上線門檻。

## 6. 驗證基線

- `manage.py check`
- `manage.py makemigrations --check`
- 完整 Django 測試
- `manage.py check --deploy` 並逐項判讀警告
- 桌機、平板、手機的關鍵路徑實機／瀏覽器驗證
- 404、500、斷線、重複送出、未填必填等失敗路徑驗證
- 建立需求、驗收情境、測試與結果的可追溯對照
- UAT 使用虛構完整資料，涵蓋現金、分期、法人、居留者、合作車行先交付、取消退款與整批進車
- 放大 200%、鍵盤操作及至少兩位 50 歲以上使用者的可用性驗證
- 每季完成一次加密備份還原演練，不以「備份檔存在」代替可還原證明

## 7. Excel 退場與採用基線

- 平行期必須明確指定系統或 Excel 何者為正式來源，不允許雙方各自修改後再人工猜測。
- 建立訂單、查詢、庫存、主檔版本、對帳、營運報表與套表均需有 Excel 退場驗收條件。
- 正式切換前，以 1 位業務與 1 位行政試點；成功後分階段擴大，不一次要求全員承擔未知風險。
- 監測不含個資的建單耗時、送出失敗、搜尋零結果、OCR 修正與說明搜尋結果，用於每週改善。
- 連續 7 天可完成日常工作且不需回 Excel 補做，才可將舊檔轉為唯讀封存。
