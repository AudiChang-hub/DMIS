# 自助式報表工作台（B 方案）

狀態：B 方案分期規格；第一階段實作與驗證紀錄見 03-release-verification.md，其餘能力不得視為已完成。

## 1. 已確認需求

- 使用者採用 B：不只建立固定報表，也需要可自行探索、修改報表資料邏輯與建立報表的工具。
- 以提供的 SUZUKI 銷售統計為案例；本輪先前已檢查 18 個可見頁面。
- 要對照 Data Studio 的完整功能範圍，不得僅交付幾張固定圖表就宣稱完成。
- 舊 Odoo、Metabase 與其資料源已退役，不得因本功能自行復原或重接。
- 現有訂單、財務、歷史快照、資料維護操作與權限須保持相容。
- 桌機頂部新增「報表中心」供檢視；「報表設計管理」另放資料維護區，只有啟用中的 admin 超級使用者可用。

## 2. 重要邊界

2026/09/08 使用者確認：傭金、獎金與實物業務計算以 DMIS 為準，不採原報表固定公式。
報表分析不得改寫正式付款。第一個財務指標讀取 `operations.dealer_commission_expense`
（標示「DMIS 車行傭金支出」，不是已付款）；不再疊加獎金分配，以免重複。
缺少 operations 的群組及整體合計顯示待補資料，不視為零；CSV 與明細同口徑。
不將實物方案設定推定為逐單已發放；實物發放與逐單成本快照不足仍列未完成。

「修改報表邏輯」預設指分類、篩選、衍生欄位、聚合、比較與顯示，不代表可由報表編輯器
修改正式訂單、改寫財務金額、重算已結算紀錄或繞過業務驗證。發現原始資料錯誤時，應
連回有權限的原業務頁面修正，由既有服務連動並留下異動紀錄。

若使用者希望連正式營運計算規則也由本工具修改，須另行確認規則權限、生效日、舊資料
處理、結算更正與回復機制；不把它混在「計算欄位」功能中默默實作。

「完整對照」不等於「已承諾一次達到 Google 產品全部功能等價」。每一類必須標記
規劃中／已實作／已驗證／外部依賴待確認，禁止用空按鈕或假資料宣稱支援。

## 3. 官方參考與功能對照方法

已查核：

- [Data Studio 文件](https://docs.cloud.google.com/data-studio)：可自訂報表、拖拉編輯與互動篩選。
- [元件設定](https://docs.cloud.google.com/data-studio/configure-report-components)：維度、指標、聚合、參數、資料融合等設定。
- [計算欄位](https://docs.cloud.google.com/data-studio/about-calculated-fields)：資料來源共用與圖表特定計算欄位分層。
- [團隊工作區](https://docs.cloud.google.com/data-studio/about-team-workspaces)：涉及 Data Studio Pro 與組織環境。

以下是 DMIS 的目標能力清單，不是聲稱每項都與 Google 有完全相同的規格、函數或授權。
來源報表的精確公式仍須透過編輯權限重新查核，不能直接套用 4 月舊稽核文件。

## 4. 目標功能清單

| 能力 | 規劃內容 | 依賴與驗收重點 |
|---|---|---|
| 資料集與資料字典 | 營運資料集、欄位型別、繁中名稱、說明、資料粒度、更新時間、品質提示 | 每欄對應實際資料來源；不能任選資料庫所有資料表 |
| 自訂欄位與指標 | 算術、條件判斷、空值、文字、日期、分群；SUM、COUNT、COUNT DISTINCT、平均等 | 函數逐一列支援範圍；金額用精確數值，不執行任意 Python／SQL |
| 共用及局部邏輯 | 共用指標、報表專用欄位、單圖專用欄位 | 顯示作用範圍與引用位置，避免修改一處意外改全站 |
| 資料融合 | 選資料集、Join 鍵、關聯方式、欄位映射與預覽 | 一對多放大台數／金額檢查；禁止未授權欄位與跨權限拼接 |
| 參數與情境分析 | 可切換期間、维度、指標及有型別的輸入參數 | 明確標記試算，不寫回原始資料；限制允許值與計算成本 |
| 報表與多頁管理 | 建立、複製、改名、分頁、排序、隱藏頁、範本、草稿、發布、停用／回復 | 所有異動有版本；不因隱藏頁而視為已限制權限 |
| 圖表與版面 | 表格、樞紐、指標卡、長條／堆疊、折線／時間序列、圓餅、散佈、區域圖等；拖拉、縮放、對齊、格線、主題 | 分批驗收；地圖資料、字型或其他外部服務另查授權及隱私 |
| 篩選器 | 複選、搜尋、日期、月／季／年、自訂與不連續期間、包含／排除、AND／OR | 區分報表／頁／群組／單圖作用範圍；顯示目前生效條件及一鍵重設 |
| 互動探索 | 點圖交叉篩選、下鑽、切維度、排序、Top N、明細、返回上一層 | 明細合計與圖表一致；不得由明細繞過資料權限 |
| 期間比較 | 前期、去年同期、增減額／率、累計與占比 | 日期基準、分母、空值及除零明確；期間長短不同有提示 |
| 異常與資料品質 | 查看空值、分類未命中、重複、缺附件／關聯、異常數字的來源與公式 | 可定位原因，不把相關性直接宣稱為因果；不自動修改原始資料 |
| 邏輯版本與發布 | 草稿預覽、新舊數字差異、受影響報表、儲存／發布／回復 | 個人探索不改共用報表；發布衝突檢查、可追溯修改者 |
| 分享及角色 | 查看、探索、編輯、發布、匯出分權；個人及團隊分類、常用報表與個人篩選 | 預設內部；首次先 admin 驗收，再由管理者明確授權其他帳號 |
| 個資保護 | 欄位遮罩、明細／匯出限制、敏感欄位拒絕引用、稽核紀錄 | 身分證、銀行、證件、憑證等不能因改圖表或匯出而外洩 |
| 匯出與列印 | PDF、CSV／Excel、列印與目前篩選條件註記 | 匯出資料與畫面同口徑；公式注入防護、大小限制、權限重新檢查 |
| 排程與通知 | 定期產出、內部通知、失敗紀錄、重跑及避免重複發送 | 外部郵件／收件人須確認；工作執行當下重驗權限，不沿用失效授權 |
| 效能与刷新 | 分頁、取消查詢、逾時、快取、更新狀態、資料異動後失效 | 快取鍵含權限、資料版本與報表版本；避免重查拖垮正式訂單 |
| 外部資料與進階延伸 | 外部資料庫、試算表、API、社群圖表、AI 協助與嵌入 | 未選服務、未授權連線／外傳、未確認成本，不能宣稱第一版全數支援 |

## 5. 使用者操作流程

### 找原因

開啟報表 → 點異常數字 → 看使用中的篩選／期間／公式 → 下鑽品牌、車型、車行等維度 →
檢查來源明細 → 判斷原始資料問題或分析口徑問題 → 連回業務頁修正，或建立報表邏輯草稿。

### 改資料邏輯

複製或開啟草稿 → 編輯分類／計算欄位 → 即時語法與型別檢查 → 預覽代表性資料 → 比對
修改前後筆數、金額與未分類項目 → 顯示引用此欄位的報表 → 有權限者發布新版本。
共用欄位與單圖欄位要有明確標示，不要使用同一個模糊的「儲存」按鈕。

### 建立報表

選資料集 → 選維度／指標 → 設定固定條件與使用者可調篩選 → 選圖表／版面 → 預覽與
明細勾稽 → 存草稿 → 設定可見與匯出權限 → 發布。可從已驗證的銷售／傭金／台數模板開始。

## 6. 現有系統銜接（已讀檔確認的入口）

- `sales/urls.py` 與 `sales/views.py` 已有營運總表與匯出入口；維持現有流程，不直接覆寫。
- `sales/models.py` 已有 SalesOrder、commission_recipient 及 effective_commission_recipient、
  台數獎金規則／結算／調整、附加獎勵品項與成本版本。
- `sales/services/operations_sync.py`、`order_commission_attribution.py` 等既有服務仍是
  業務連動的權威，不以報表自訂公式取代。
- 初期新增獨立報表工作台；資料集要先核對實際欄位與既有計算服務，再建立查詢層。
- 新增資料表、migration、快取方案、圖表套件均尚未定案，不得把概念名稱當作現有功能。

## 7. 財務與計數必測

- 同一訂單有多筆贈品、補助、收入／支出時，台數與金額不能倍增。
- COUNT 與 COUNT DISTINCT 的差異、空車身號碼、退單、取消及領牌日期空值有明確定義。
- 實際銷售車行與獎金歸屬車行可區分，不抹除原來源。
- 收款價、實收、應收、已收清、應付傭金與已付款不能互相冒名。
- 實物數量、禮券面額、成本、點數不可混加為金額。
- 原有淨利公式、生效版本與訂單快照不由自助報表改寫。
- 報表計算欄位若與正式「淨利」不同，要標記「試算」且不得冒用正式指標名稱。
- 日期邊界、季／月多選、閏年、分母為零、空值、負數、精度與四捨五入皆有測試。

## 8. 安全與 UX 最低要求

- 所有 API 後端驗證資料集、欄位、Join、操作與匯出權限；不能只隱藏前端按鈕。
- 計算使用解析器與允許的型別／函數；拒絕任意 SQL、eval、跨網路函數及高成本運算。
- 桌機以編輯為主、手機以查看／篩選／下鑽為主；不能把桌機畫布縮小就當手機版完成。
- 檢視、探索、編輯模式清楚分開；固定儲存區、未儲存離開提示、撤銷／重做、錯誤定位。
- 空資料、無權限、公式無效、資料載入失敗、資料過期與背景更新中必須分別顯示。
- 拖拉需有滑鼠、觸控及鍵盤替代操作；下拉層級、彈窗、sticky 區塊及橫向溢出要實測。

## 9. 待取得的必要資訊

1. 原報表編輯模式：確認完整頁面、圖表與固定篩選、計算欄位、資料來源及融合。
2. 舊資料來源與目前 Django 的欄位／粒度差異；不能恢復已刪除資料源作為捷徑。
3. 台數、傭金、收清及獎勵等不明確的正式口徑，須以現有業務服務及使用者確認為準。
4. 「全部功能」的外部項目：需要哪些來源、是否對外分享、誰收排程、AI 是否允許外傳。
