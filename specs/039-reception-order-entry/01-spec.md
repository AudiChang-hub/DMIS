# 建立訂單與查詢分離（B 方案）

## 範圍

- 主導覽為首頁、建立訂單、全部訂單、營運總表、報表中心、資料維護區；手機及常用功能一致。全部訂單不再放建立按鈕。
- 建立入口優先選車／選色，無展示瀏覽權限而有下單權限者直接填單。沿用共用訂單 view／表單，不新增第二種訂單資料。
- 接待頁採精簡導覽，只留建立訂單與明確「離開接待」；不自動顯示其他訂單、待接單數、財務管理選單。
- 接待填單固定採對客售價與有效分期，admin 也不在此編輯內部財務；後端忽略偽造財務、佣金、附加費與自接單欄位。原內部建檔 URL 與舊草稿保留相容性，須具備建立及內部訂單操作權限。
- 接待送出固定先待接單；成功及重送均到本筆確認頁，僅建立者可讀，內容只包含編號、車款、顏色與接單狀態，提供再建立及主動離開接待。內部後續編輯／接單維持原流程。
- 接待草稿限本人；不得誤載其他人或內部舊草稿，避免洩漏或清掉既有財務。接待不連線內部協作廣播，草稿、附件、證件與查價 API 均須檢查權限及資料範圍。

## 權限與相容

- 新增獨立 order_intake 查看／操作授權，和 catalog 瀏覽權限歸於「建立訂單」大項。orders 僅管理查詢及既有訂單操作。
- 一次性 migration 將已設定且具有 orders 查看＋操作者的舊建立能力搬至新權限；不授予新查詢／財務能力，不覆寫已存在的新授權。記錄版本與稽核，避免舊權限表單覆寫。
- 車行可分別設定瀏覽、建立、查詢，不再強迫建立者擁有整間車行查詢權限。停用或撤權即時生效。
- 接待查價只回傳公開方案，不允許使用 order_id 查其他訂單快照。查詢／媒體／WebSocket 不因新增建立權限而擴權。
- 保留既有訂單與金額／快照公式，不改業務欄位。既有常用功能代碼保留，建立連結改導向接待入口。

## 驗證與發布

- 測試內部與車行的僅建立、僅查詢、撤權、跨帳號草稿／附件／確認頁、偽造財務與重送；舊建檔／編輯及 PG 併發回歸。
- 桌面、平板、手機與鍵盤實際 UI 驗收；不在正式站建立測試訂單。
- 相容新增 1.7.0，更新依權限顯示的說明／版本歷程。完整 CI 後 tag、備份、T470P 部署、健康與正式只讀驗收。
- 回復以保留新權限資料與接待草稿為原則，不移動已發布標籤、不刪除訂單或權限稽核。
