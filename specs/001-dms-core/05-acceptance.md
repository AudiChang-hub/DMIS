# 驗收條件 (05-acceptance)

## 庺穎/環境
- `docker compose up` 為一鍵啟動 Odoo + PostgreSQL
- `make smoke` 在 180 秒內得到 200/302/303 回應
- PR 若修改 `addons/**` 或 `docker-compose.yml`，且未同步更新 `specs/**`，CI 必須失敗

## UI/UX 改善驗收條件

### 列表（tree view）
- 列表不顯示「簡稱」（`short_name`）欄位、不顯示「縣市」（`city`）欄位。
- 列表預設顯示欄位（optional="show"）：車行代碼、店名、負責人、店長、電話1、手機、車行類型、品牌、啟用（共 9 欄，≤15）。

#### 欄位選擇器（Column Chooser）
- [ ] 車行列表右上角欄位選擇器可看到所有業務欄位（包含：地址、備註、電話2、手機/傳真、電子信箱、4 個價格表、LINE群組、年節送禮、三陽/台鈴排車容量）
- [ ] 勾選/取消勾選任意欄位後，列表即時更新
- [ ] 預設顯示欄位數量 ≤ 15
- [ ] 「店名/負責人/店長/電話1/手機」出現在欄位選擇器列表（可被取消勾選），而非只能固定顯示
- 手動驗收：開啟車行列表 → 右上角欄位選擇器 → 應能看到所有業務欄位；使用無痕視窗或清除 localStorage 後測試（Odoo optional 選擇儲存於瀏覽器）

#### 欄位顯示硬性上限（15 欄）
- [ ] 勾選第 1–15 個欄位均可正常顯示，無任何錯誤
- [ ] 嘗試勾選第 16 個欄位時：被阻止（欄位維持隱藏），同時畫面出現 warning notification（標題「欄位顯示上限」，內容含「15 個欄位」說明），且 **checkbox 不維持勾選狀態**（dropdown 重新開啟後確認未勾選）
- [ ] 取消勾選任一欄後，再嘗試勾選原本被阻止的第 16 欄：應可成功（回到 ≤15）
- [ ] 取消勾選操作永遠允許，不被阻擋
- 手動測試流程：
  1. 開啟車行列表（無痕視窗或清除 localStorage）
  2. 預設 9 欄顯示
  3. 逐步從欄位選擇器勾選至 15 欄（應可成功）
  4. 嘗試勾選第 16 欄 → 必須被阻止 + 出現 warning toast
  5. 取消勾選任一欄 → 再勾選原第 16 欄 → 應可成功

### 基本資料 labels
- 車行名稱、負責人 labels 在 form 中清楚可見（顯示欄位標題，非僅 placeholder）。

### 店長同負責人
- 勾選「同負責人」後，店長欄位立即帶入負責人姓名（onchange 生效）。
- 負責人變更且「同負責人」仍勾選時，店長同步更新。
- 取消勾選後，店長姓名保留（不自動清空）。
- 透過 API（create/write）傳入同負責人勾選時，亦能防呆同步。

### 車行類型與品牌
- 車行類型可從下拉選單選擇（`dms.dealer.type` 主檔）。
- 品牌可多選（many2many_tags widget），支援多品牌車行。
- 多品牌保存後再次開啟仍存在（Many2many 正確儲存）。

### 明細可編輯
- 點進車行明細預設為編輯模式（不需再手動點 Edit 按鈕）。

### labels 粗體（若 SCSS 已加入）
- form view 中所有欄位 label 呈現粗體，區塊分隔清楚。

### 手動測試案例
1. 建立車行，填入負責人「張大哥」，勾選「同負責人」→ 店長自動顯示「張大哥」。
2. 修改負責人為「李老闆」（保持勾選）→ 店長同步變更為「李老闆」。
3. 取消「同負責人」勾選 → 店長保持「李老闆」，不被清空。
4. 選擇品牌「三陽」和「台鈴」→ 儲存後重開，兩個品牌仍存在。
5. 開啟車行列表，確認欄位清單不含「簡稱」「縣市」。

### 複製動作（Duplicate）
- [ ] 車行列表右上角 Action 下拉選單出現「複製」項目
- [ ] 選擇一筆車行紀錄並執行「複製」→ 新增一筆複製記錄，`code` 為 `{原code}-C`（若已存在則嘗試 `{原code}-C2` 依此類推）
- [ ] 複製後的 `code` 與任何現有記錄不重複（唯一約束不違反）
- [ ] 可同時選取多筆執行「複製」，每筆均產生新紀錄並帶有唯一 `code`
- 手動測試：車行列表 → 選擇任一記錄 → Action → 複製 → 確認新記錄出現且 code 為 `{原code}-C`

## 產品管理 (dms.product) 驗收條件

### 模型
- [ ] `dms.product` 可新增、儲存、編輯、刪除
- [ ] `brand_id`（品牌）為 Many2one → `dms.brand`，必填，下拉選單可選
- [ ] `name`（名稱）必填，留空時儲存失敗並提示
- [ ] `energy_type`（能源型式）必填，Selection 含「油車」與「電車」兩選項

### 視圖 / UX
- [ ] `DMS → 產品管理` 選單存在且可進入 tree/form
- [ ] tree view 顯示：品牌、名稱、型號、煞車型式、能源型式、顏色（共 6 欄）
- [ ] form view 有 4 個分頁：基本資料、動力規格(油車)、動力規格(電車)、車身規格

### 動力分頁條件切換
- [ ] 選擇「油車」時：「動力規格(油車)」分頁**顯示**，「動力規格(電車)」分頁**隱藏**
- [ ] 選擇「電車」時：「動力規格(電車)」分頁**顯示**，「動力規格(油車)」分頁**隱藏**
- [ ] 「基本資料」與「車身規格」分頁永遠顯示，不受 energy_type 影響
- [ ] 切換 energy_type 後分頁即時更新，無需儲存或重整頁面

### 欄位選擇器（Column Chooser）
- [ ] 產品列表右上角欄位選擇器包含所有業務欄位（含動力規格、車身規格共 28 欄）
- [ ] 預設顯示欄位：品牌、名稱、型號、煞車型式、能源型式、顏色（共 6 欄）
- [ ] 勾選第 1–15 個欄位均可正常顯示，無任何錯誤
- [ ] 嘗試勾選第 16 個欄位時：被阻止（欄位維持隱藏），畫面出現 warning notification，且 checkbox **不維持勾選狀態**
- [ ] 取消勾選操作永遠允許，不被阻擋

### 手動測試流程
1. DMS → 產品管理 → 新增產品
2. 填入品牌（選現有品牌）、名稱「Test 油車」、能源型式選「油車」
3. 確認「動力規格(油車)」分頁出現、「動力規格(電車)」分頁消失
4. 切換能源型式為「電車」→ 確認分頁立即切換
5. 填入車身規格資料 → 儲存 → 重開確認資料正確
6. 在列表中確認 6 個欄位均顯示
7. 嘗試不填品牌或名稱儲存 → 應顯示必填錯誤
