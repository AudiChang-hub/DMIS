# 1.14.0 開單公司與文件資料留存

## 核准範圍 B

- admin 在合作車行「訂購單公司資訊」管理公司全名、統編、列印地址與電話；馭盛同一套設定，入口亦在列印範本設定。
- 人員沿用 OrderAccountProfile 所屬車行。正式下單時 dealer 取所屬車行公司，店內取 home；帳號僅提供新單預設，不能決定重印抬頭。
- 訂單另外保留公司 ID、版本與當時文字，與來源、佣金歸屬分開；公司更新、人員轉店與 admin 代印不覆蓋舊文字。
- 公司設定不完整不阻擋接單，但正式訂購單／個資同意書／合併簽署文件回覆 409，提供 admin 確認入口；不得 fallback 馭盛。
- admin 可在本單選擇實際開單公司、填原因並確認，包含採用同公司最新版；鎖定訂單並檢查 revision，保留前後值、操作者與時間。不呼叫財務重算，不修改已簽附件。
- 個資同意書僅店家落款及 PDF 作者使用本單公司，既有原廠條款不自行改寫。
- 車行可從本車行訂單或下訂完成頁列印訂購單／合併簽署文件，沿用查詢訂單授權；逐筆範圍檢查，不開放其他匯出或內部財務。接待完成頁不需先進入全部訂單。

## 舊單、資料與回復

- 0148 僅新增公司、留存欄位、稽核表及既有馭盛設定。既有訂單沒有可靠開單公司歷史，現今帳號歸屬也可能改過，因此不批次推定；第一次要重產文件時由 admin 明確確認。
- 舊簽署檔案仍可讀取，不重產覆寫；原收款、附件、成本、佣金、訂單來源不修改。
- 稽核保留訂單編號；訂單永久刪除時外鍵 SET_NULL，不阻擋已批准的刪除流程。
- 備份 DB／媒體後部署。若故障優先向前修正；不可直接回復舊 PDF 程式對外服務（會重新固定印馭盛）。必要時停用文件產生入口，保留新增欄位與稽核，修復後重開。資料庫還原須維護窗口並對帳發布後的新資料，不直接 reverse migration 刪掉留存。

## 驗收

- admin 專屬設定／更正、車行隔離、重印不變、缺資料阻擋、帳號轉店、來源與銷售方不同。
- 修改原因／確認必填、公司與訂單 stale revision 拒絕、設定無 GET 副作用。
- 舊訂單不猜測；既有簽署檔與財務值不變；不新增財務稽核／同步。
- PDF 兩聯與合併文件同公司、metadata、中文與長字串無重疊。
- 桌機／平板／手機公司設定、預覽與操作；發布完整 CI、T470P 備份、部署及登入後唯讀驗證。
