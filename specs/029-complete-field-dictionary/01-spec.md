# 029－完整欄位、營運資料與歷史匯入規格

## 目的

以目前的訂單、庫存、車型、成本與合作夥伴系統為基礎，完整承接既有 Excel 的有效資料與實際作業流程，並移除已確認不需要的舊欄位與固定統計表。

本規格為 2026-08-04 逐題確認後的業務基準；尚未表示所有功能皆已實作。

## 來源

- `車輛進銷貨庫存表(客戶資料).xlsx`
- `車行、網路平台.xlsx`
- 現行 Django 訂單、庫存與車型功能
- 使用者逐題確認的欄位語意與例外規則

## 核心原則

1. 訂單、庫存、成本與財務資料只輸入一次，由系統產生分析與文件。
2. 主檔異動不得影響已成立訂單；價格、成本、獎勵、牌險、分期與客服資訊都要保存快照。
3. 售價版本只維護「建議售價（含牌險）」與「現金價」；電動車牌險依品牌、輕型／重型領牌級別及實際領牌日套用固定領牌規費與強制險。
3. 車輛成本依實際領牌日期認列；進車不產生成本。
4. 配車由人員主動執行，系統不得自動配置。
5. 單筆淨利只反映新車銷售；中古車與配件獲利分開，但報廢代辦收入及報廢車收入明確納入單筆淨利。
6. 歷史資料不強迫符合現行必填規則，預設唯讀並保存原始值。
7. 平行使用期間 Excel 為正式來源；新系統正式切換後 Excel 改為唯讀備查。

## 已確認的單筆淨利公式

```text
單筆淨利
= 實際撥款
- 車輛成本
- 車輛相關支出
+ 車輛相關收入
+ 實銷獎勵金
+ 促銷補助金
+ 分期補貼息
+ 強制險傭金
+ 信用卡傭金
```

其中：

- 車輛相關支出包含領牌、強制險、選號、贈品、運費、車行傭金、台數獎金等。
- 車輛相關收入包含領牌、強制險、代辦、選號、其他、報廢代辦與報廢車收入。
- 刷卡向客戶收取與銀行實扣手續費的差額屬實際損益。
- 中古車處理獲利與配件獲利不得納入。

## 日期基準

| 用途 | 日期基準 |
|---|---|
| 成本、獎勵、牌險版本 | 實際領牌日期 |
| 分期方案版本 | 訂單日期 |
| 單筆淨利歸屬月份 | 實際領牌日期 |
| 銷售分析預設 | 實際領牌日期 |
| 銷售分析可切換 | 訂單日期、實際交付日期 |

## 驗收重點

- 同一識別號碼在移除空格、連字號並轉大寫後不得重複建立。
- 訂單與歷史匯入資料可完整搜尋，搜尋結果須標示命中欄位。
- 歷史匯入不因缺少現行必填欄位失敗。
- 任何主檔版本更新不得回寫舊訂單。
- 固定統計表不得搬入；統計需由交易資料即時計算並可下鑽。
