# 歷史與增量匯入規格

## 來源權責

- 平行試營運期間：Excel 為正式來源。
- 正式切換後：新系統為唯一正式來源，Excel 唯讀備查。
- 匯入由管理者在網頁上選擇檔案、預覽差異並確認，不使用固定 Windows 或 Ubuntu 路徑。

## 匯入批次

每批保存檔案名稱、SHA-256、大小、操作人、上傳時間、來源工作表、預覽結果、確認時間、成功/略過/衝突/錯誤筆數及原始檔封存位置。

來源 Excel 中消失的資料不得自動刪除；只標示來源已移除並交由管理者處理。

## 銷貨頁籤

正式欄位列為第 3 列。主要校正：

- A 序號取消；系統自行編訂單號，來源列號只追溯。
- B/AR 合併為實際領牌日期，B 優先。
- E/AT 合併為車主名稱，AT 車主資料區優先。
- G 永久保存為歷史收款價，不直接視為車款售價。
- J/K 轉多筆實際收款。
- AO 的 V 轉為確認收款。
- BB 是發票日期；CH 是訂單日期。
- BF/BG 依實際內容交換為匯款帳號與銀行名稱/分行。
- BR `YYYYMM` 轉舊車出廠年月 `YYYY/MM`。
- CC 改為標配贈品；CI 改為公司實體贈品；CL 改為銷售方案分類。

歷史補助只保存總額，不擅自拆分三個申請單位的金額。狀態轉換後仍永久保留原始文字。

### 新車與中古車交易辨識

- 同一引擎／車身號碼可以先有一筆新車銷售，日後再有一筆中古車交易；兩筆是不同交易，不得以實體車輛識別號碼直接合併。
- 中古車強訊號限於：車行欄位等於「中古車」、備註等於「中古車」或包含「中古車買賣」、補助方案包含「中古車過戶」。一般的「中古車估價」不是中古車交易。
- 銷貨重複判斷鍵由「車輛識別、車輛類別、交易日期、車主」共同組成；完全相同交易仍判為衝突。
- 同一識別號碼出現兩筆以上新車交易時維持衝突，必須由人員查證並把後續交易改為中古車或排除錯誤列。
- 中古車交易建立獨立歷史訂單與財務快照，但不連結、不占用也不扣除新車庫存。
- 舊版預覽批次缺少車輛類別時，重新驗證會補上系統推論；人工已指定的類別不得被覆蓋。
- 工作表尾端若只剩公式產生的 `0`，且沒有車型、識別號碼、車牌、日期、證號或電話，視為空白公式列並自動略過，不建立假訂單。

## 進貨頁籤

- 數量 1：目前可售庫存。
- 數量 0 且能對應銷貨：歷史已售車輛並連結歷史訂單。
- 數量 0 且無法對應銷貨：封存待確認，不計入可售。
- 全部歷史車輛皆匯入；未對應車型建立停用的歷史占位車型。

引擎/車身號碼比對鍵一律轉大寫並移除空格與連字號，原始值仍保留。標準化後重複者不得自動合併。

## 舊規格衝突

`specs/023-excel-import/01-spec.md` 使用 Excel 序號 `excel_sync_id` 作 upsert 主鍵，已不符合本輪決策。後續實作前必須以本規格取代，不得再以 Excel 序號作業務主鍵。

## 驗證報告

匯入前後至少輸出：

- 來源/匯入/略過/衝突/錯誤筆數
- 重複標準化識別號碼
- 車主名稱雙欄差異
- 無法分類的刷卡/分期手續費收入
- 無法對應車行、平台與車型
- 來源已移除但系統仍存在的資料
- 可售庫存與 Excel 數量 1 的筆數及逐車差異

## 匯入校正工作台

- 原始 Excel 與逐列 `raw_data` 永久保持不變；人工修正只更新本次批次的暫存映射值。
- 衝突依「工作表＋標準化識別號碼」成組比較，不能只顯示衝突筆數。
- 待確認批次允許逐列「修正後匯入」或「不匯入此列」，每次決定保存處理前後資料、原因、人員及時間。
- 每次修正後重新計算重複識別號碼、處理狀態、未對應主檔與庫存差異。
- 尚有 `conflict` 或 `error` 時禁止確認匯入；人工排除視為已完成處理，但不寫入正式資料。
- 待確認或處理失敗的批次可以刪除，並在資料庫交易成功後刪除來源檔；已完成批次只能封存，不得直接刪除正式資料與稽核鏈。

### 待補主檔工作台

- 未對應車型與通路必須能在同一個匯入頁面處理，不要求使用者離開後再回來重新檢查。
- 每個 Excel 原始名稱可選擇「對應既有主檔」、「快速建立新主檔」或「保留歷史文字」。
- 車型快速建立只收匯入必要資料與已知顏色；售價、成本、獎勵及分期方案仍在正式車型頁維護。
- 通路快速建立只收類型、名稱與地址；聯絡人、品牌合作及傭金規則仍在正式通路頁維護。
- 對應關係跨批次沿用，名稱比對採 NFKC、忽略大小寫與空白，但 Excel 原始文字不得被改寫。
- 「保留歷史文字」適用於展場、朋友推薦等非正式主檔分類；匯入仍保存原始文字，且不得建立污染主檔的假車行或假車型。
- 儲存任何處理後立即重新驗證批次，並顯示剩餘未對應數量、處理人與時間。
