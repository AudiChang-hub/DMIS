# 合作車行代開單與單筆查閱授權（方案 B）

## 已確認範圍

- 建立人保存實際操作者；銷售來源是實際銷售車行；佣金歸屬不授予訂單存取權。
- 內部人員於共用建立訂單的來源選「代合作車行開單」，確認所選車行公司資料。未設定完整或公司版本已變動時不得送出；成立時保存該公司快照，不依未來列印者重新推導。
- 外部帳號固定其啟用中的所屬車行，不得透過 POST 改來源或公司。接待畫面不開放內部財務。
- 本車行資料範圍包含同車行、由馭盛代開的訂單；本人範圍仍不自動擴大。admin 沿用帳號與權限／車行帳號設定範圍。
- 待接單即能依授權列印訂購單、個資同意書或合併文件；列印不代表已接單，也不變更狀態。

## 單筆例外

- admin 由訂單「查閱與列印授權」選合作車行人員；查看與列印分別勾選，須填原因，可撤銷，保留操作紀錄。
- 新增 `OrderCustomerAccessGrant`，唯一鍵為訂單＋帳號 profile。授權版本衝突或審核後身份改變時拒絕舊表單；權限變更和事件紀錄在同一交易完成。
- 單筆授權只增加客戶版清單／明細、允許的客戶附件及客戶簽署文件範圍，不增加編輯、領牌、交付、接單、財務、補助或其他列印權。
- 仍受帳號啟用、車行啟用、查詢及客戶文件列印功能權限限制。無一般查詢權但有列印權者可由已授權文件網址列印；不因此開放訂單列表。
- 撤銷額外授權不否定原本本人／本車行範圍的存取權。停用帳號不能使用；轉換身份或所屬車行會遞增 `identity_epoch`，舊授權即使轉回原車行亦不自動復活。一般功能旗標調整不改 identity epoch。
- 不更改訂單來源、建立人、佣金、金額、公司快照或已簽附件，不批次移轉舊單。

## 修改與驗證

- 檔案：`sales/intake_forms.py`、`views.py`、`services/print_company.py`、`services/order_customer_access.py`、`models.py`、`order_customer_access_views.py`、共用權限／路由與對應模板、`static/js/assisted-order.js`。
- 測試：`test_assisted_orders`、既有訂單權限／接待／公司列印／帳號測試；PostgreSQL 驗證授權、移轉及列鎖；桌機 1440、平板 820、手機 390 檢查代開確認、授權／撤銷及待接單文件入口。
- 前後比對正式 audi 既有角色、車行、範圍、功能授權；不覆寫管理者設定。針對已確認舊單的例外採專用授權服務與稽核，不改銷售來源。

## 發布與回復

- 1.16.0，migration 0150 僅新增授權表及 profile 身份代次，既有訂單、帳號設定不變。
- 發布前 PostgreSQL 與媒體備份，完整 CI 通過後附註標籤發布。正式頁面驗證與必要的單筆授權均記錄；不以正式訂單演示代開或財務寫入。
- 優先前向修復。需回復時使用前一已驗證程式並保留新增資料表，先停用外部新增授權入口；舊版不使用新授權，不能還原整庫覆蓋發布後訂單。
