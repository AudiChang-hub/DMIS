# DMIS 使用者手冊（Odoo 16 社群版）

> 版本：v1.1.0　適用系統：DMIS on Odoo 16 Community　最後更新：2026-03-27

---

以下說明如何在 DMIS 系統中操作各模組，讓新使用者能一步一步完成日常工作。  
介面名稱以繁體中文為主，操作流程依照模組功能分區介紹。

若您是第一次登入，請先取得您的帳號與密碼，並在瀏覽器輸入系統網址（例如 `http://<伺服器位址>:8069`）進入 Odoo 登入畫面。

---

## 登入與基本操作

1. 開啟瀏覽器並輸入 Odoo 系統網址（例如：`http://localhost:8069`）。
2. 在登入頁面輸入您的**帳號（Email）** 與**密碼**後，按下「登入」。
3. 登入後，畫面上方會顯示應用程式選單，如「車行管理」、「客戶管理」、「銷售管理」、「產品管理」、「財務結算」、「報表分析」、「使用者管理」等。

Odoo 中常用的按鈕：

| 按鈕 | 說明 |
|------|------|
| **建立** | 用於新增資料 |
| **儲存** | 在編輯頁面保存輸入的內容 |
| **捨棄** | 取消編輯，回到上一頁 |
| **匯出** | 將清單資料匯出為 CSV/Excel |
| **過濾 / 分組 / 收藏** | 在清單檢視中快速篩選或分組資料 |

## 1. 車行管理（dms_core）

### 功能

- 管理車行（經銷商）的基本資訊。
- 作為其他模組（如銷售、財務）的關聯資料來源。

### 操作流程範例：新增一個車行

1. 從上方主選單點選 **「車行管理」** 進入車行清單。
2. 點擊 **「建立」** 按鈕，進入車行表單。
3. 填寫車行資訊：
   - **車行名稱**：例如「台北民生門市」。
   - **代號**：供內部識別使用，可自訂，如「TP-MS」。
   - **地址、電話、聯絡人** 等欄位。
4. 確認填寫無誤後，點擊 **「儲存」**。新的車行即會出現在清單中，後續在銷售訂單或財務結算時可選擇此車行。

> **提示：** 若有大量車行需要匯入，管理員可使用「匯入」功能批次建立（使用 CSV/Excel 檔案）。

## 2. 產品管理（dms_product）

### 功能

- 維護產品模板、可販售產品項 / SKU、價目版本、分期規則與費用類型。
- 以內部查找效率為優先，主畫面以清單為主，不以圖片為核心。
- 正式入口位於 **「產品管理」** App。

### 操作流程範例：建立產品模板與產品項

#### 建立產品模板

1. 進入 **「產品管理 → 產品模板」**。
2. 點擊 **「建立」**。
3. 填寫模板資訊：
   - **品牌**
   - **機種**：例如 `JET`、`MMBCU`、`Saluto`
   - **型式**：可視需要填寫
   - **型號**
   - **能源型式**
4. 點擊 **「儲存」** 完成模板建檔。

#### 在模板中建立產品項

1. 進入 **「產品管理 → 產品模板」**，開啟一筆模板。
2. 切換到 **「產品項」** 頁籤。
3. 直接在清單中新增一筆產品項。
4. 填寫：
   - **產品模板**
   - **內部唯一代碼**：若不手動輸入，系統會依「型號 + 出廠年份」自動產生，例如 `UC125DA-2026`
   - **出廠年份**：直接以年份文字輸入與顯示，例如 `2026`
   - **車色**
   - **啟用狀態**
5. 系統會自動同步 legacy 相容欄位，供銷售模組持續使用。
6. 若同一型號與出廠年份下有多筆 SKU，系統會自動補尾碼，例如 `UC125DA-2026-02`。
7. 按下 **「儲存」** 完成建檔。
8. 若產品項被停用，仍會保留在模板的 **「產品項」** 頁籤中，可直接再勾回 **啟用**。
9. 模板清單中的 **SKU 數量** 只統計目前啟用中的產品項，停用項不會計入。
10. 若要快速建立相近模板，可從右上角 **Action / 動作** 選單使用 **複製**，系統會一併帶出產品項，再依需要微調。
11. 若某筆產品項尚未被價格、訂單或其他資料引用，可直接在模板的 **「產品項」** 頁籤按垃圾桶刪除。
12. 若同一模板下只差顏色或少數欄位，可直接在 **「產品項」** 頁籤使用該列的 **複製**，系統會先複製一筆，再修改差異欄位即可。
13. 使用 **複製** 時，系統會自動重生新的 **內部唯一代碼**，不需要手動先改代碼再儲存。

> **提示：** 同一模板下，不同車色與不同出廠年份可建立多筆 SKU；請勿只依賴中文名稱辨識產品。

## 3. 客戶管理（dms_customer）

### 功能

- 建立與維護購車客戶資料。
- 在銷售訂單中直接輸入客戶姓名即可，不需預先建立客戶。
- 如預先建立，可提高資料一致性並支援後續聯繫。

### 操作流程範例：建立新客戶

1. 在主選單點選 **「客戶管理」**，進入客戶清單。
2. 點擊 **「建立」**。
3. 填寫客戶資料：
   - **客戶姓名**（必填）。
   - **身份證字號、生日**：若需要核對補助或活動資格，可填寫。
   - **地址、電話、Email**：方便通知車輛領牌或維修等資訊。
4. 儲存後，即可在銷售訂單中透過搜尋選擇此客戶。若未先建立，在銷售訂單中輸入「客戶姓名」亦可自動建立基本資料。

> **提示：** 客戶資料越完整，後續 BI 報表分析更準確，例如可依性別、年齡層分析銷售趨勢。

## 4. 價格與分期規則（dms_product）

### 功能

- 以價目版本管理價格，不再把售價直接塞回單一產品主檔。
- 可維護現金價、牌價、分期規則模板、費用類型與規則掛接。
- 入口位於 **「產品管理」** App 下的 **「價目版本、價格基準、分期規則模板、費用類型、規則掛接」**。

### 操作流程範例：建立價目版本與價格基準

1. 進入 **「產品管理 → 價目版本」**，建立一筆版本資料：
   - **名稱**
   - **生效日**
   - **狀態**：草稿 / 生效 / 封存
   - **備註**
2. 進入 **「產品管理 → 價格基準」**，建立對應價格：
   - **價目版本**
   - **產品項 / SKU**
   - **現金價**
   - **牌價**
3. 若需維護分期規則，進入 **「產品管理 → 分期規則模板」** 建立規則，再於規則明細設定：
   - **起始期數 / 結束期數**
   - **採用價格基準**（現金價 / 牌價）
   - **費用明細**（開辦費、設定費或其他可擴充費用）
4. 進入 **「產品管理 → 規則掛接」**，將 **SKU × 價目版本 × 分期規則模板** 綁定。
5. 銷售訂單查價時，系統會自動抓取 `生效日 <= 訂單日` 的最新有效版本；若新結構尚未建資料，才 fallback 讀取舊 `dms.vehicle.price`。

## 5. 銷售管理（dms_sale）

### 功能

- 建立銷售訂單，追蹤車輛售出流程。
- 自動帶入售價、牌險費、車行傭金等。
- 管理訂金、尾款及付款狀態。

### 操作流程範例：建立新的銷售訂單

1. 點選 **「銷售管理」** 進入訂單清單，按 **「建立」**。
2. 填寫銷售訂單表單：
   - **訂單日期**：系統預設為今日，可修改。
   - **車行**：若為車行交易，選擇對應車行，系統會依規則嘗試帶出傭金。
   - **客戶**：可直接輸入客戶姓名，或從既有客戶清單中選擇已建檔客戶。
   - **車款**：選擇要銷售的產品（SKU），系統將優先依據新產品管理模組的價目版本自動帶入售價；若未建新價格，則 fallback 舊相容價格資料。
   - **顏色**：從顏色清單選擇顏色。
   - **付款方式**：選擇「現金」、「分期」等，決定支出手續費。
   - **付款資訊**：可填寫訂金，系統會自動計算尾款；若已結清，可勾選 **已結清** 並填寫 **結清日期**。
   - **牌照險費**：若車款為電動車，選擇車款後系統可自動帶入牌照 + 強制險費用；傳統油車僅顯示必要項目（強制險/領牌費/其他）。
   - **精品明細**：可新增購買的精品，例如安全帽、車罩等，輸入數量與單價，系統會計算小計。
   - **舊車收購**：若客戶以舊換新，可輸入舊車估價與報廢資訊。
   - **備註**：其他交易說明。
3. 確認內容後**儲存**。
4. 如需紙本報件單，於訂單右上方可新增**報件單**或使用列印功能產出。
5. 欲前往財務結算，可點擊表單中的 Smart Button **「查看財務結算」**。

### 付款狀態與金流提醒

在銷售訂單中，可填寫**訂金**，系統會自動計算**尾款**；若交易完成，可勾選 **已結清** 並填寫結清日期。請依公司流程向客戶確認收款。

## 6. 財務結算（dms_finance）

### 功能

- 對單筆銷售訂單進行收支與淨利計算。
- 自動帶入預設收入及支出明細，可自行調整或新增。
- 支援 15 種收入類別與 11 種支出類別，並可由管理者動態維護類別清單。

### 操作流程範例：建立財務結算

1. 在 **「銷售管理」** 的訂單表單中，點擊 **「查看財務結算」** Smart Button。如尚未建立結算紀錄，系統會自動建立一筆並開啟編輯頁面；如已存在則顯示列表可選擇。
2. 在 **財務結算** 表單中，系統已預帶以下資訊：
   - **訂單**：對應的銷售訂單。
   - **客戶與訂單日期**：從訂單自動帶入。
   - **收入明細**：如「售價收入」、「代辦費收入」、「強制險收入」等；數值從訂單及價目表取得。
   - **支出明細**：如「牌險費支出」、「車行傭金支出」、「強制險支出」等；數值從訂單或牌照費設定帶入。
3. 檢查並修改必要項目：
   - 如有額外支出或收入，可點擊各明細行右側**新增**以加入新類別。
   - 若某項費用由公司吸收，可將金額改為 `0` 或負值（代表退費）。
4. 表單底部會自動計算**總收入、總支出及淨利**，負值會以紅色標示。
5. 確認無誤後，點擊 **「儲存」**。結算即完成，可用於後續財務報告。

### 類別管理

管理員可在 **「財務結算 → 類別管理」** 選單中維護收入/支出類別。  
點擊 **「建立」** 可新增類別，設定欄位包括：

| 欄位 | 說明 |
|------|------|
| **名稱** | 顯示於明細中的描述 |
| **代號** | 系統用來預設帶入明細（如 `license_fee`、`dealer_commission`） |
| **類型** | 收入或支出 |
| **順序** | 顯示排序 |

透過這個機制可以動態增刪類別，免去修改程式。

## 7. 報表分析（dms_report）

### 功能

- 提供即時的銷售、利潤及傭金分析。
- 支援 Pivot 及圖形視圖，可由使用者互動篩選。

### 系統預設的報表

| 報表名稱 | 資料模型 | 說明 |
|---------|---------|------|
| **銷售報表** | `dms.sale.order` | 以「月份 × 車款」展示銷售數量，可切換 Pivot 或長條圖 |
| **利潤報表** | `dms.sale.finance` | 以「月份 × 淨利/收入/支出」交叉分析淨利構成 |
| **傭金報表** | `dms.sale.order` | 在銷售報表中勾選「車行」分組，統計各車行每月銷售台數或傭金 |

### 基本操作

1. 從主選單進入 **「報表分析」**，選擇欲查看的報表（銷售、利潤或傭金）。
2. 系統會顯示預設的 Pivot 表格。您可以：
   - 使用上方 **「樞紐分析」** 工具，自行拖曳字段至列或欄，調整群組方式。
   - 切換至圖表視圖（柱狀圖、折線圖等），快速比較趨勢。
   - 透過搜尋欄位新增**篩選條件**，例如限定日期區間、特定車款或車行。
3. 可使用右上角的 **「匯出」** 功能，將報表下載為 Excel 作進一步分析。

> **提示：** 若資料量龐大，建議先在上方加入日期或車行篩選，再展開其它維度，可提升效能。

## 8. 報表規則管理（dms_report_rule）

### 功能

- 讓使用者自訂報表規則，建立專屬的分析視圖。
- 規則包括選擇模型、圖表類型、維度、指標及篩選條件。

### 操作流程範例：建立自訂報表規則

1. 在 **「報表分析」** 下點選 **「報表規則」**（或稱「報表規則管理」）。
2. 點擊 **「建立」** 新增規則。
3. 填寫以下欄位：

   | 欄位 | 說明 |
   |------|------|
   | **報表名稱** | 自訂規則名稱，例如「車行別月銷售分析」 |
   | **模型** | 選擇要分析的資料模型，例如 `dms.sale.order`（銷售訂單）或 `dms.sale.finance`（財務結算） |
   | **圖表類型** | Pivot、長條圖、折線圖或圓餅圖 |
   | **維度** | 點選新增，從彈窗中挑選日期/車行/車款等欄位（可多選） |
   | **指標** | 選擇要統計的數值欄位，如 `amount_total`（總銷售額）、`net_profit`（淨利）等（可多選） |
   | **篩選條件** | 以 Odoo Domain 語法輸入條件，例如 `[('state', '=', 'done')]` 表示只分析已完成訂單；支持 `safe_eval`，輸入前請確認語法安全且正確 |
   | **擁有者** | 預設為建立者，可設定**公開（public）**是否允許他人查看此規則 |

4. 儲存後，在表單上方點選 **「預覽報表」** 按鈕，系統會依規則即時產生對應的報表。
5. 若滿意此報表，可透過**複製**功能調整其他維度/指標；也可在主選單中新增快捷方式供常用分析。

### 權限設定

- 使用者必須至少擁有 **報表規則使用者** 群組，才能建立與編輯自己的規則。
- 規則資料的存取：
  - 預設只能看見自己建立的規則；勾選**公開**可讓所有使用者查看。
  - 只有擁有者或 Admin 才能修改/刪除規則。

## 9. 虛擬欄位管理（dms_report_virtual）

### 功能

- 讓使用者像 Looker Studio 一樣建立「虛擬欄位」（計算分類欄位），無需修改程式碼。
- 虛擬欄位可作為報表規則的維度，對資料動態分類後再進行分組統計。

### 適用情境

- 將各個車行依名稱歸類為不同「品牌群組」或「地區」。
- 依訂單金額區間自動分類為「高消費」、「中消費」、「低消費」。
- 依客戶生日月份分類為「一～三月」、「四～六月」等季節群組。

### 操作流程範例：建立虛擬欄位

1. 在 **「報表分析 → 虛擬欄位」** 選單中點擊 **「建立」**。
2. 填寫基本資訊：
   - **名稱**：顯示用名稱，例如「品牌類別」。
   - **代號**：英數底線組成，系統識別用，例如 `brand_group`（不可重複）。
   - **資料模型**：選擇此虛擬欄位對應的模型，例如 `dms.sale.order`。
   - **預設值**：若所有規則均不符合，顯示的預設分類，例如「其他」。
   - **公開**：勾選後其他使用者可讀取但不能修改。
3. 在 **分類規則** 頁籤中，點擊**新增**加入規則列：

   | 欄位 | 說明 |
   |------|------|
   | **順序** | 規則評估順序，數字小的先套用 |
   | **比對類型** | `contains`（包含）、`regex`（正則表達式）、`python`（Python 表達式） |
   | **欄位路徑** | 要比對的欄位名稱，支援點號路徑，例如 `dealer_id.name`（`python` 類型不需填寫） |
   | **比對條件** | 包含的關鍵字或正則表達式內容（`python` 類型不需填寫） |
   | **Python 表達式** | 僅 `python` 類型使用，可用 `record` 變數與 `re`、`math` 函式庫，回傳非 `False` 的值即作為分類結果 |
   | **分類結果** | 符合此規則時輸出的分類值（`contains` / `regex` 類型使用） |

4. 規則會由上至下逐條評估，**第一個符合的規則**決定分類結果，若全部不符合則顯示預設值。
5. 儲存後，可點擊表單右上角 **「測試虛擬欄位」** 按鈕，輸入一筆記錄的 ID 即可立即查看計算結果與逐規則評估日誌。

### 在報表規則中使用虛擬欄位

1. 進入 **「報表分析 → 報表規則」** 並開啟或建立一筆規則。
2. 切換至 **「虛擬維度」** 頁籤。
3. 在 **虛擬維度** 欄位中選擇已建立的虛擬欄位（可多選）。
4. 點擊 **「預覽報表」**，系統會對最多 1,000 筆資料進行 Python 側計算分組，以表格呈現各分類的筆數與指標合計。

> **注意：** 虛擬欄位為 Python 側計算，不使用原生 SQL `GROUP BY`，建議在報表規則的篩選條件中縮小資料範圍，以確保效能。若筆數超過 1,000 筆，表格頂部會顯示截斷警告。

### 比對類型範例

#### contains（包含關鍵字）

| 欄位路徑 | 比對條件 | 分類結果 |
|---------|---------|---------|
| `dealer_id.name` | `台北` | 台北區 |
| `dealer_id.name` | `台中` | 台中區 |

#### regex（正則表達式）

| 欄位路徑 | 比對條件 | 分類結果 |
|---------|---------|---------|
| `dealer_id.name` | `台北\|新北\|基隆` | 北北基 |
| `dealer_id.name` | `台中\|彰化\|南投` | 中彰投 |

#### python（Python 表達式）

```python
# 依訂單金額分層（欄位路徑不填），回傳非 False 值即作為分類結果
'高消費' if record.amount_total >= 150000 else ('中消費' if record.amount_total >= 80000 else False)
```

> 可用變數：`record`（當前記錄）。可用函式庫：`re`、`math`。不允許匯入其他套件。

## 10. 常見問題與注意事項

**Q：資料重複輸入怎麼辦？**  
系統設計盡量減少重複輸入。例如在銷售訂單中輸入車款、價格與客戶資料後，財務結算會自動帶入相關收入支出明細。若仍需要紙本文件，可透過列印功能取得，無需手寫。

**Q：修改訂單後財務結算會自動更新嗎？**  
不會自動更新歷史資料。請手動開啟結算重新檢查與保存。

**Q：報表資料沒有顯示最新建立的資料？**  
Pivot/Graph 報表資料為即時查詢。若剛建立資料無法顯示，請重新整理頁面或檢查篩選條件。

**Q：看不到「建立」按鈕或某些欄位？**  
可能是權限不足。請聯繫系統管理員調整權限組別。

**Q：匯入資料時失敗？**  
匯入前請先下載範本並按照欄位順序填寫，以避免失敗。各模組清單頁均提供匯入及匯出功能。

**Q：虛擬欄位規則使用 `python` 類型有安全疑慮嗎？**  
系統使用 `safe_eval` 並限制白名單（僅 `re`、`math`），不允許執行任意系統指令或匯入外部套件。管理員仍應限制 **虛擬欄位 Admin** 群組成員，以避免不當使用。

## 11. 後續建議

- **學習 Odoo Domain 語法**：在報表規則的篩選條件與進階搜尋中，熟悉 Domain 語法可提升查詢精準度。
- **使用分群與收藏**：在清單檢視中，可將常用的分組與過濾條件「加至收藏」，下次點擊收藏即可直接套用。
- **多模組串連**：建議銷售流程與財務結算緊密連結，例如在訂單確認後立即建立財務結算，確保收支資料完整。
- **虛擬欄位效能**：如需對大量資料分析，V2 版本預計支援將虛擬欄位結果儲存為計算欄位（stored compute field），以支援原生 SQL `GROUP BY` 加速。
