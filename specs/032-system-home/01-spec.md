# 系統首頁與營運總表整合（B 方案）

## 已確認範圍

取代 031 規格的頁面分工：首頁提供帳號、實際執行版本、更新內容、公告及授權捷徑；不載入公司財務或訂單清單。營運總表集中本月成果、同期比較、十二月趨勢、收款風險與工作量，不再顯示逐筆訂單。查單及草稿統一在全部訂單處理。

admin 可新增、編輯公告，設定草稿／發布、置頂、起訖時間。公告以純文字顯示；未發布、未到期及已過期的內容不提供一般人員。保留修訂軌跡與版本衝突保護；不提供不可復原刪除，以取消發布回收。

## 權限與相容

- 首頁為登入後安全入口。保留 dashboard URL 名稱，舊首頁搜尋轉到已授權的全部訂單。
- dashboard 授權鍵保留，改名為營運總表的「全公司戰情指標」；operations 鍵仍控制財務彙總及既有匯出。兩者任一可進入營運總表；只有 dashboard 可見原有庫存、工作量等公司指標。車型財務彙總與累計實收僅 operations 可見。
- 訂單明細、庫存、操作與匯出仍各自驗權，不因合併自動取得權限。
- 舊營運總表查詢連結轉至全部訂單；日期、風險、能源及收款條件一致，空白日期不隱式刪除。
- 已取消／已退款使用深石墨底白字與取消符號，不弱化整列，不修改財務底層資料或公式。

## 驗收與部署

- 公告發布起點包含、結束時間不包含，以台北時間輸入；結束必須晚於開始。
- 伺服器強制 admin 管理，POST/CSRF、純文字跳脫、同時編輯衝突測試。
- 首頁無財務與客戶資料；營運總表無逐筆清單；趨勢／風險導向正確訂單集合。
- 手機、桌面、深淺主題；指南與導覽同步更新。
- Django 與 PostgreSQL CI、備份、正式部署、健康檢查和瀏覽器驗證。

## 回復方式

0132 僅新增公告與修訂資料表，不回填或改寫訂單。若需回復應用程式，使用前一個已驗證版本並保留新增資料表，避免丟失已發布公告；不要反向刪除 migration 資料表。部署前依既有腳本備份 PostgreSQL 與媒體。
