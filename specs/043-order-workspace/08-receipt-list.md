# 收款明細列表（核准 B）

## 操作與資料

- 預設只顯示訂金；新增列五個主要欄位為確認、項目、實收、日期、方式。項目旁選客戶／分期公司分類，名稱不參與分類判斷。
- 附件、備註、刷卡金額與手續費可展開，不新增第二套帳務。編輯、刪除、分類改動沿用財務權限、鎖定、版本檢查及 OrderChange。
- 原系統 balance／installment_disbursement 無實收、確認、日期、附件、帳戶、備註及刷卡資料時只呈現為「應收設定」。不刪除／覆寫舊應收、人工調整原因或歷史資料；新增真正收款由使用者決定。
- Schema 只加 PaymentRecord.receipt_kind；migration 依既有 system_key 分類分期撥款，不猜測舊人工名稱，不修改金額。
- 系統應收仍按原價款公式與手動調整計算。人工新增收款預設應收零，實收不會自動轉成應收；既有人工應收仍保留額外義務。
- 確認款項依分類分別加總。分期公司款不能抵客戶欠款；存檔、取消確認及刪除均刷新摘要、收清、對帳與財務快照。保留既有人工額外應收逐筆核清規則。
- 交付以已確認客戶收款檢查。cash_receivable_v2 新單包含訂金確認；舊單維持原先只檢查扣訂金後尾款的交付條件，不新增歷史阻擋。車行先交付例外不變。
- 分期公司多筆確認合計進入 actual_disbursement；平台沿用非訂金客戶款同步。撤回最後一筆仍按原快照還原，不覆蓋後續人工改值。佣金／成本公式不變。

## 驗證與發布

- 單元／請求：預設列、應收保存、分類、分次確認／取消／移除、人工應收、舊附件、交付、報表、權限、稽核及第二次原地儲存。
- 桌機 1440、平板 820、手機 390 真實瀏覽器新增與儲存，以隔離測試資料庫執行；正式站僅讀取及本地輸入驗證，不送出正式訂單。
- 發布前完整 CI（含 PostgreSQL 財務併發）、備份與 release tag；發布後版本／健康／登入頁面驗證。

## 回復

- 先停止應用寫入，再備份當下 DB 與媒體；保留 0147 新欄位，不倒退刪除分類。
- 尚未產生新版收款時可回復前版應用；已產生多筆人工分期收款時不可直接回退舊同步邏輯。優先修補前進；若必須整體還原，須先核對發布後異動，依備份還原流程及明確授權處理，不以舊備份直接覆蓋新資料。
- 沒有刪除正式付款、交易或附件的批次腳本。
