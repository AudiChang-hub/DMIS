# 匯入財務修復、訂單成立日與視窗版面（方案 B）

## 已確認需求
- Excel 匯入成立日等於領牌日；缺領牌日保留空白並提示待補。
- 系統建立的成立日為首次儲存當日，後續修改不變。
- 原 order_date 留作既有價格／分期版本依據，新增獨立 established_on，禁止因回填日期重算歷史快照。
- 100% 顯示下導覽列、資料維護選單、報表側欄須留在視窗範圍。

## 財務口徑
- 已核對原檔公式有 G-H-SUM(L:S)+SUM(W:AL) 與 G-H-SUM(L:V)+SUM(W:AL) 兩種版本。
- 使用各原始欄位重建，與原「單筆淨利」比較；不以淨利差額捏造收入或支出。
- 收款價用於歷史計算基礎，不代表已收款；不更動 PaymentRecord 或確認旗標。
- 原漏映射的手續費、中古車、合併贈品運費、獎金、其他收入補齊，保留四位小數。
- 逐筆記錄公式口徑、來源值、系統前後值與差額。無法核對者、已修改的財務與退訂換買家訂單跳過，不覆寫。
- 批次修復預設唯讀，套用需預覽摘要雜湊；交易鎖、修訂號、異動紀錄與可重跑防護。
- 原 Excel 不修改；正式修復前備份資料庫與媒體。
- 匯入成立日回填完成後不隨一般領牌改期漂移；原缺日者於第一次補上領牌日時補成立日。
- 報表新增「訂單成立日期」依據，舊設定的 order_date 保留為「訂單版本日期」，不偷偷改既有報表口徑。

## 修復與還原
1. 執行既有部署備份並驗證 gzip；記錄備份路徑與修復前版本。
2. `python manage.py reconcile_legacy_finance --details`：僅輸出逐筆前後值、来源與核對結果；輸出含財務資料，僅存受限備份區，不提交 Git。
3. 核對統計後執行 `python manage.py reconcile_legacy_finance --apply --expected-digest <預覽摘要>`。資料有變即拒絕整批寫入，須重新預覽。
4. 再次預覽應僅剩 already_reconciled／待人工核對。人工修改或原始差異會保留且標示，未核對者不列入淨利合計。
   具備營運資料操作權限者可逐項修正並勾選「我已核對本單收支」，必須填寫依據；由既有交易鎖與異動紀錄保存人員、時間及金額。
5. 修復紀錄保留每欄前值，可按異動紀錄精準還原；整版還原依 docs/RESTORE_DRILL.md，使用部署前資料庫／媒體備份與原映像。不可直接反向縮減小數欄位（會損失精度）。

## 驗收
- 兩種公式、零值、負值、小數、缺失／非法數字、人工修改、重跑、摘要失效與回滾測試。
- 新舊訂單日期與歷史價格快照保持測試。
- 桌機／平板／手機及鍵盤導覽測試；完整 CI 通過後部署 T470P，核對健康與逐筆修復統計。
