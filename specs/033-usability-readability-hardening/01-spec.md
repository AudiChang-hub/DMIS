# 033 易用性、閱讀與辨識強化｜Spec

## 目標

- 修正手機核心流程的水平溢出與難以操作問題。
- 讓首頁、全部訂單與營運總表使用相同的全欄位搜尋規則。
- 讓傳統機車經銷商能快速辨識狀態、金額、下一步與可操作區域。
- 在不改動既有營運欄位、計算公式、訂單快照與流程條件下，統一桌機與手機體驗。

## 不可破壞範圍

- 不變更訂單、庫存、補助、領牌、交付、對帳及單筆淨利的欄位語意。
- 不變更有效日期、成本、獎勵、傭金與訂單快照的計算規則。
- 保留證件照片查看／替換／刪除、動態資料列新增／刪除、自動暫存及多人編輯防護。
- 手機與桌機可採不同資訊密度，但不得隱藏完成工作所需的功能。

## 功能需求

### 1. 全欄位搜尋一致性

- 首頁、全部訂單及營運總表必須使用相同的正規化規則。
- 大小寫、空白及連字號不得改變搜尋結果，例如 `ABC-1234`、`abc1234` 與 `ABC 1234` 應得到相同訂單。
- 搜尋結果應顯示命中的欄位名稱及內容，且保留個資遮罩。
- PostgreSQL 查詢必須保留使用 `pg_trgm` GIN index 的條件。

### 2. 手機核心版面

- 390px 寬度下，全部訂單搜尋、狀態篩選與搜尋按鈕不得超出畫面。
- 統一撥款對帳在手機上改為單筆卡片，訂單、對帳對象、金額、日期、帳戶、確認與儲存具清楚層級。
- 訂單工作頁籤若可水平滑動，需顯示可滑動提示及目前位置，不可讓後續頁籤無提示地藏在畫面外。

### 3. 閱讀與辨識

- 操作文字與狀態標籤不得低於 13px；主要欄位、按鈕及數值以 14px 以上為原則。
- 手機主要操作目標至少 44×44px。
- 待處理、進行中、完成、異常、取消使用不同語意色，並保留文字，不以顏色作為唯一判斷。
- 金額統一使用千分位並靠右對齊。
- 動態配件及其他費用欄位使用與主表單相同的控制項樣式。

### 4. 大量選項

- 車行／平台、車型及車色提供可輸入搜尋的選擇器。
- 車色在選擇車型前維持停用，選擇後只顯示該車型的啟用顏色。
- 車型資料列表的顏色數量只統計啟用中的顏色，停用顏色仍保留供歷史資料使用，但不得混入可選顏色數量。
- 同一車型輸入與既有顏色同名的顏色時，必須沿用原資料並重新啟用，不得建立第二筆；若是將另一筆歷史顏色改成既有名稱，原歷史顏色保留為停用，既有訂單與庫存關聯不得改寫。
- 選擇器必須保留原生 `select` 作為送出資料與無 JavaScript 備援。

### 5. 系統診斷與說明

- 公開健康檢查維持最少資訊；登入後的系統診斷需顯示資料庫、Redis、背景工作佇列與媒體磁碟狀態。
- 使用說明補上建立訂單、OCR、工作頁籤、快速進車、領牌、交付及對帳的畫面辨識示例。

## 驗收條件

- 390×844、430×932、820×1180、1440×900、1920×1080 無非預期水平溢出。
- `ABC-1234`、`abc1234`、`ABC 1234` 搜尋結果一致，並顯示相同命中摘要。
- 手機可在不橫向捲動整頁的情況下完成一筆對帳。
- 主要手機操作區至少 44px；狀態、金額與錯誤在 200% 放大下仍可辨識。
- Django 完整測試、migration 檢查、部署檢查及正式站 smoke test 通過。
