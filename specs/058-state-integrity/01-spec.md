# 狀態機清理、併發鎖定與庫存留痕（Phase 3）

批准：使用者 2026-09-29 授權部署後自動續做 Phase 2、3；以下採建議方案。

## 範圍與接受條件

- M6 狀態清理：移除未使用的車輛狀態（待調車、調車中、待交車）與訂單狀態（待調車、調車中）；調車只記位置。
  正式站核對時沒有資料處於這些狀態；migration 仍保守對應（訂單→已配車；車輛有配車→已預留，否則→可銷售）。
  「車況異常」改為可用：未配車的車輛可在庫存編輯勾選暫停配車（須填車況說明），取消勾選恢復可銷售，狀態異動留在庫存紀錄。
- 集中狀態轉移：`SalesOrder.STATUS_TRANSITIONS` 與 `ensure_transition()`，由接單外的流程方法（配車、改配、領牌、交車、取消、撤銷取消、例外結案）檢查。
  直接 `save()` 與匯入的 `update()` 不經此檢查，避免影響歷史匯入。
- L1 併發：`complete_registration`、`complete_delivery`、`request_cancellation`、`reallocate`、`withdraw_cancellation` 自行鎖定訂單列並重讀狀態，不依賴呼叫端。
- M7 庫存留痕：配車、改配（兩台車）、交車、取消、例外結案都寫庫存異動紀錄；交車紀錄移入 model，畫面不再重複寫。
- M5 配車：記錄 `allocated_at`；選車依出廠年月、進車日期先進先出；顯示同車型車色待配車排隊位置。
  非第一順位或未選最早出廠車輛時須填原因（`allocation_skip_reason` 與事件）。配車超過 30 天未領牌列入待辦與「配車保留逾期」篩選。
- L2 重複取消已在 Phase 1 阻擋；L3 取消待退款可撤銷，回到待配車（未接單則待接單），原配車已釋回需重配；L4 訂單編號撞號自動重取。

## 資料變更

Migration `0154_state_cleanup_allocation_queue`：新增配車時間與插隊原因欄位、更新狀態選項；資料步驟只處理已移除狀態（正式站為 0 筆）。
既有已配車訂單的 `allocated_at` 為空，不列入逾期判斷。

## 不在範圍

發票、通知（Phase 4）；外部串接冪等（L5，之後再議）。

## 回復

欄位可為空，可退回前版程式；若退回後需要舊調車狀態，只能重新加入選項（目前無資料使用）。
