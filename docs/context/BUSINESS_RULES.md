## 訂單與接待

- 系統只給本店人員使用（2026-10-16）：車行不開登入帳號、不代車行開單、不設定車行的訂購單公司資訊；訂單來源分本店、車行、網路平台三種。建立訂單的人就是接單人，建立後直接進入待配車（`order_intake.mark_accepted`），沒有待接單與「由我接單」。建立訂單七步：車款與車價（車型、車色、來源、付款方式與車價同一步）→車主與證件→汰舊與補助→選號與交車→配件（可略過，2026-10-17 加回；沒有必填配件，空白列不存）→訂金與費用（最上方列車價、牌險費、配件加購與合計，指定號碼有選號費時多列選號費；訂單備註也在這步）→確認送出（`services/order_wizard.py`）。接待不能露出其他客戶訂單或內部財務。
- 下單必填只留後續流程會用到的欄位（2026-10-14）：車型、車色、車主姓名、證件號碼／統編（客戶依此歸戶）與各條件必填（車行來源、分期、無售價時的車價、送達／託運目的地、價格或優惠原因）。電話、地址、交車方式、電動車 Email、證件照片、自動辨識與人工核對都是選填，簽署前也不必補；送出時證件未完成會寫入處理紀錄。入口 `SalesOrderForm.clean`、`order_wizard_views.identity_status`、`test_order_wizard.py`。其他頁同原則（2026-10-14）：舊車估價、未繳稅金、補助金額空白＝0；收車人電話選填；配件數量空白＝1、臨時配件工資空白＝0（類型與售價仍必填）；交車四項核對仍必勾，可用「全部已核對」一次勾選。測試 `test_optional_fields.py`。
- 「其他」配件自動進主檔（2026-10-15 選 A）：建立或修改訂單儲存後，可訂價人員輸入的「其他」加購配件，名稱（去多餘空白、不分大小寫）不在配件主檔時自動建立並啟用，售價／工資取首次輸入；同名已存在不新增也不改價；贈送不加入；主檔備註與訂單處理紀錄記來源。入口 `services/accessory_catalog.learn_custom_accessories`、`test_store_handles_orders.py`。
- 下單「訂金與費用」步驟：所有可建立訂單的帳號（含接待模式）都可填訂金金額、日期與付款方式，成為未確認的訂金收款列；有收款確認權限的店內人員可勾「已收到這筆訂金」於建立時直接確認入帳（2026-10-14，須選付款方式，未填日期取當天）（其餘由店內確認實收後才入帳，取消仍只看已確認實收）；其他財務欄位權限不變。可另填「總價優惠」（減少金額或折數，填了就必填原因，須大於零且不超過優惠前總價），送出即以送出人直接核定（備註「下單時填寫」），不經待確認，訂購單即為最終金額。入口 `sales/services/order_discount.py`、`test_intake_deposit_discount.py`。
- 建立與查詢分開授權；內部管理需使用者主動進入。訂單資料範圍分本人建立／全公司，另可逐筆授權。
- 訂單成立日不同於領牌日；歷史 Excel 缺訂單日期依既有匯入規則採領牌日，系統建立採成立時間。不可混用圖表日期口徑。
- 已完成訂單仍可依權限修正，保留原因、修改人與前後紀錄；不暗中重置交付／結算狀態。
- 刪除經專用流程與稽核；不得直接 SQL 刪除來繞過關聯檢查。正式資料批次合併另須確認衝突與交易邊界。
- 刪單的車輛（2026-10-19 使用者決定）：未領牌、未交車＝放回可銷售（只有預計領牌日不算領牌）；已領牌（車牌或領牌完成）未交車＝停用、標「刪單待確認」，admin 判斷是否改回；已交車的訂單不可刪除（admin 強制也不行），改走「交車後退車」；例外：Excel 匯入的歷史單（有 `legacy_snapshot`）匯入錯誤時 admin 可作廢（軟刪除、可還原，重匯由交易鍵略過），沒收過的仍不可刪（2026-10-19 使用者決定）。入口 `order_deletion.permanent_deletion_blockers`、`_change_effects`。

- 現行入口是 `sales/services/legacy_import.py`；財務還原見 `legacy_finance.py`。Odoo 的 excel_sync_id 規格不是目前實作。
- 營運 Excel（銷貨表頭在第 3 列、進貨在第 1 列）**依表頭名稱取值，不依欄位字母**；對照表是 `SALES_HEADER_ALIASES`／`INVENTORY_HEADER_ALIASES`，Excel 改欄名時在那裡補別名。缺必要表頭（車種型號、引擎／車身號碼、車主名稱）會寫入 `preview_summary.blocking`，`confirm_import` 拒絕匯入；其餘缺少的表頭只進 `warnings`。財務欄位仍依 `legacy_finance.MAPPING` 的表頭名，改名時補 `LABEL_ALIASES`。

## 財務與權限
- 營運總表「車款成交額」（`services/sales_metrics.vehicle_sale_amount`）：訂單車價合計；匯入單車價為 0 時改用匯入快照的收款價（不含強制險），只用於報表、不回寫訂單（2026-10-12）。

- admin 指定哪些人可調整下單金額；此授權不連帶開放成本、佣金、淨利、報表或其他車行資料。
- 傭金支出（`dealer_commission_expense`）建立訂單即帶入，之後訂單同步（未領牌、未取消、未鎖定、非匯入單）隨主檔重算：車行單＝機種基礎傭金＋該車行品牌加減＋已結算台數獎金；本店單來源為本店人員且未指定歸屬車行時＝該人員 `staff_commission`；本店單指定給車行仍不新增基礎傭金。人工覆寫（`manual_financial_fields`）不被覆蓋，領牌完成鎖定（本店單同樣鎖定）。入口 `apply_order_dealer_commission`、`sync_order_operations`、`test_finance_ledger.py`。
