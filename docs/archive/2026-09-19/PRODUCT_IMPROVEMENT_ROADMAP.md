# 車輛銷售管理系統｜產品改善與品質藍圖

版本：1.0
日期：2026-08-06
適用對象：產品負責人、實際使用者代表、開發與驗證人員

## 一、結論

這套系統目前已具備訂單、OCR、庫存、配車、補助、領牌、交付、營運、對帳與資料維護的主要閉環。下一階段不應把 Excel 原樣搬到網頁，也不應為了視覺更新而重寫；正確方向是：

> **保留 Excel 的熟悉感，消除 Excel 的重複輸入、找不到版本、無法追蹤、容易誤改與多人衝突。**

要讓傳統機車經銷商「願意用、用得快、出錯能救、越用越離不開」，產品必須同時做到：

1. **今天該做什麼一眼看懂**：首頁是工作戰情，而不是數字展示牆。
2. **想找什麼直接輸入**：保留不先選欄位的 Excel 式搜尋，並說明命中原因。
3. **重要流程有防呆但不綁死**：頁籤可平行處理；真正不可跳過的條件才阻擋。
4. **錯誤可理解、可回復**：說明為何失敗、去哪裡修、資料是否已保存。
5. **手機與桌機各自好用**：手機適合現場下單與拍照；桌機適合列表、對帳、主檔與大量資料。
6. **資料安全不是靠提醒**：帳號、權限、檔案驗證、稽核、備份與查修線索都要成為系統能力。

## 二、使用者與工作情境

| 使用者 | 最常用裝置 | 核心任務 | 最怕發生的事 |
|---|---|---|---|
| 業務 | 手機 | 客人面前建立訂單、拍證件、選車、列印 | 畫面卡住、資料消失、客人等太久 |
| 行政 | 桌機＋手機 | 配車、補助、領牌、交付、文件 | 漏件、車與文件對錯、期限忘記 |
| 庫存人員 | 桌機／平板 | 快速進車、調車、車況 | 重複號碼、位置不準、配錯車 |
| 財務／管理者 | 桌機 | 撥款對帳、成本、淨利、版本維護 | 金額被回寫、找不到依據、逐單核對太慢 |

### 傳統經銷商的設計假設

- 年齡與數位熟練度差異大，但多數熟悉 Excel、LINE、紙本與手機拍照。
- 偏好「看得到所有資料」而非多層選單；但一次顯示太多必填會造成壓力。
- 對技術名詞沒有義務理解。畫面只使用業務語言，例如「保存當時資料」，不用「snapshot」。
- 對系統最重要的信任來自：資料不會不見、數字有依據、誰改的查得到、錯了救得回來。

## 四、產品設計準則

### 1. 熟悉但更安全

- 搜尋、表格、排序、篩選與匯出延續 Excel 心智模型。
- 不提供可破壞公式或歷史資料的自由編輯。
- 主檔採生效版本，訂單保存當時價格、成本、獎勵與客服資訊。

### 2. 一個畫面有一個主要目標

- 主要按鈕不超過一個視覺最高層級。
- 刪除、取消、完成等高風險動作使用明確文字與確認。
- 可新增的項目一定有對應移除；已被採用的歷史資料改為停用或沖銷。

### 3. 防呆只擋真正危險的事

- 配車與補助可平行，不做硬性逐關 Wizard。
- 一般客戶未領牌不能交付；合作車行依規則可先交付。
- 已有領牌資料不能直接換車；已交付不能改核心訂單。
- 自動計算可人工修正時，必須留下原因與修改人。

### 4. 每個狀態都讓人知道發生什麼

- 上傳後 500ms 內顯示「已接收／處理中」。
- OCR 可在背景進行，完成後通知回來核對。
- 送出中阻止重複點擊。
- 離線明確顯示「尚未同步」，不得假裝已保存。
- 錯誤摘要說明數量、原因，點擊可到欄位。

### 5. 對中高齡使用者友善

- 主要正文至少 16px，手機重要文字建議 17px。
- 操作目標至少 44×44px，不用只靠小圖示。
- 文字與圖示並用，不以紅／綠色作唯一狀態。
- 相同動作使用相同名稱與位置。
- 顯示實際例子，不用抽象欄位定義。

## 五、目前已落地的本階段改善

- 任務導向、可搜尋、可列印的登入後使用說明。
- 全站「使用說明」入口，會帶到目前頁面相關章節並另開，不中斷輸入。
- 表單錯誤摘要、逐項欄位定位與輔助科技說明連結。
- 重複送出保護與「處理中」狀態。
- 手機／桌機斷線持續提示，不誤稱已離線同步。
- 400、403、404、500 End User 錯誤頁。
- 每個請求的查修編號與 `X-Request-ID`。
- 目前 Django 系統的 End User 手冊與例外排除內容。
- 所有主要文件上傳已統一檢查實際內容、大小、損壞與偽裝格式。
- Excel 匯出已阻止公式注入，對帳返回網址已限制為站內安全路徑。
- 登入連續失敗限速、12 小時滑動式工作階段與含個資檔案禁止快取。
- Docker 映像改採必要檔案 allowlist、非 root 帳號，並新增 Django 專用 CI。

## 六、分階段改善路線

### P0：安全與可教學（正式擴大使用前）

1. **統一安全上傳管線**
   - 已完成大小、MIME、實際內容、圖片解析、PDF 結構與 Office 容器檢查。
   - 待正式環境補上惡意程式掃描與隔離區，再開放不受信任的外部人員自行上傳。
2. **角色權限**
   - 業務、行政、庫存、財務、主管、系統管理員。
   - 檢視、下載、修改、完成、核准分開授權。
   - 不在角色實測前直接切換，避免中斷現場。
3. **登入防護**
   - 失敗限速、異常通知、閒置逾時、管理員／主管 MFA。
   - 敏感密碼查看需重新驗證與查看原因。
4. **使用說明完成度**
   - 以虛構資料補齊主要畫面截圖。
   - 每次 UI 發版必須同步更新手冊。

### P1：每天更快（Excel 明顯退出）

1. 全部訂單：全欄位搜尋、日期、來源、車型、付款、負責人、排序、分頁、儲存檢視。
2. 訂單頂部：建議下一步、缺少資料、負責人、期限，點擊直達頁籤與欄位。
3. 上傳元件：預覽、確認、進度、重試、替換、刪除與一致錯誤文案。
4. 對帳與營運表格：固定表頭／首欄、未儲存列、批次確認、離頁警告。
5. 客戶與所有成長型清單：伺服器分頁、快速篩選與空狀態說明。
6. 本機待同步佇列：只在具備可靠重試、冪等鍵與衝突處理後啟用。

### P2：熟手與新手都順手

1. 標準／舒適顯示模式。
2. 新手顯示完成度與短說明；熟手保留長表單、鍵盤操作與批次功能。
3. 資料維護搜尋、最近使用與我的最愛。
4. WCAG 2.2 AA、axe 自動檢查、鍵盤操作與焦點管理。
5. 戰情首頁依角色分層：今日待辦優先，主管 KPI 第二層。

### P3：進階自動化

- LicenseWatcher 搬至中央伺服器後的自動監控與回傳。
- 電動車／微型電動二輪車牌險完整規則。
- 個人化看板、常用篩選、通知與跨裝置未完成工作。
- 對外客戶入口、電子簽署或補件連結（另行做資安與法遵評估）。

## 七、軟體驗證流程

每一項功能的 Definition of Done：

1. Spec 記錄正常流程、例外、欄位語意與不可破壞條件。
2. 涉及資料庫時有 migration、資料轉換、重跑與 rollback 評估。
3. Service／模型規則有單元測試。
4. View、表單、權限、成功／拒絕路徑有整合測試。
5. 關鍵流程有桌機與手機端到端驗證。
6. 390×844、820×1180、1440×900 無重疊；表格以外不得水平溢出。
7. `manage.py check`、`makemigrations --check`、完整測試、`check --deploy`。
8. 上傳功能測試副檔名偽造、錯誤 MIME、損壞檔、超大檔與重複提交。
9. End User 說明、畫面文字與版本同步更新。
10. 上線前備份；部署後 smoke test；失敗有明確 rollback。
11. 每個需求建立「需求 → 驗收情境 → 自動／人工測試 → 結果」對照，避免只有測試數量、沒有證明使用情境。
12. UAT 必須使用虛構但接近真實的完整資料，涵蓋現金、分期、法人、居留者、合作車行先交付、取消退款與整批進車。
13. 每季實際做一次備份還原演練，記錄可接受資料損失時間（RPO）與恢復時間（RTO）；不能只確認備份檔存在。
14. 依賴套件、容器映像與機密設定納入弱點檢查；高風險項目修正或完成書面風險接受後才能擴大使用。

## 八、Excel 退場與門市導入計畫

系統上線不等於 Excel 自然消失。建議採 30 天導入，不讓平行期無限延長：

| 階段 | 做法 | 可前進條件 |
|---|---|---|
| 第 1 週：影子操作 | 1 位業務、1 位行政以系統完成真實工作，Excel 只核對 | 主要流程無資料遺失；阻斷問題有處理人 |
| 第 2 週：小組主用 | 試點人員以系統為正式來源，Excel 不再反向修改 | 建單、配車、領牌、交付與對帳成功率 ≥ 95% |
| 第 3 週：全員切換 | 全體新訂單進系統，舊 Excel 僅供查詢 | 重複輸入下降 ≥ 80%；每日能完成交班 |
| 第 4 週：停止新增 Excel | 將 Excel 改為唯讀封存，訂定例外補登流程 | 連續 7 天無人需靠 Excel 才能完成工作 |

### Excel 功能退場對照

| 原本在 Excel 做的事 | 系統正式位置 | 退場驗收 |
|---|---|---|
| 找客人與歷史訂單 | 全欄位搜尋、客戶資料 | 知道任一線索可在 10 秒內找到 |
| 新車銷售資料 | 訂單＋營運資料 | 不再重複手抄相同欄位 |
| 引擎／車身號碼與位置 | 庫存、配車、調車歷程 | 庫存數與現場抽查一致 |
| 成本、售價、獎勵 | 車型生效版本＋訂單快照 | 修改新版不影響已完成訂單 |
| 分期／平台／車行入帳 | 統一對帳 | 預計、實際、差額可在同頁確認 |
| 月報與單筆淨利 | 營運總表與匯出 | 抽查結果與正式單據一致 |
| 報件單與信封 | 列印套表 | 不需回 Excel 套印即可完成 |

切換期間要指定一位「資料裁決者」。系統與 Excel 不一致時，由其依正式單據決定，禁止各人自行選擇對自己方便的版本。

## 九、可用性驗收

建議找 5 位未參與開發、熟悉 Excel 的實際使用者：2 位業務、2 位行政／庫存、1 位財務／管理者，其中至少 2 位 50 歲以上。

| 任務 | 驗收門檻 |
|---|---|
| 建立一般現金訂單 | 中位數 ≤ 6 分鐘；P90 ≤ 9 分鐘 |
| OCR 上傳 | 1 秒內知道已受理；P95 15 秒內完成或給出修正建議 |
| 找任一訂單 | 知道任一姓名／電話／證件／車牌時 10 秒內找到 |
| 找到操作說明 | 30 秒內找到對應主題 |
| 七項指定任務 | 首次 90% 無需口頭指導；一週後 95% |
| 錯誤復原 | 90% 不需求助即可恢復 |
| 平行使用兩週 | Excel 重複輸入量下降至少 80% |
| 滿意度 | SUS ≥ 80；任務滿意度 ≥ 4.3/5 |

除分數外，每週記錄五種不含個資的產品訊號：建單耗時、送出失敗原因、搜尋無結果、OCR 人工修正欄位、使用說明搜尋但無結果。若同一問題連續兩週進入前三名，必須排入改善而不是只增加教學文字。

## 十、效能與容量標準

- 一般點擊回應 P75 ≤ 200ms。
- LAN／一般手機 P75 LCP ≤ 2.5 秒。
- 10,000 筆訂單全欄位搜尋 P95 ≤ 300ms；50,000 筆 ≤ 500ms。
- 草稿保存 P95 ≤ 1 秒；失敗不能覆蓋較新的本機內容。
- OCR 與大型匯入在背景工作，不阻塞 Web request worker。
- 重複送出不得產生重複訂單、文件、退款或收款。
- 每月檢查 DB、媒體檔、log、備份與磁碟成長；設定容量預警而非等磁碟滿才整理。

## 十一、資訊安全與營運韌性

- **資料分級**：身分證、居留證、存摺、密碼為高度敏感；合約、補助、領牌文件為機密業務資料；報表匯出仍視為內部資料。
- **最小權限**：角色權限上線前以真實工作情境驗收；證件下載、密碼查看、財務修改與完成狀態需分開授權及留痕。
- **保存與刪除**：依已確認的永久保存需求保留結案證件；若法規或公司政策變更，先做資料盤點與核准流程，不由人員直接刪檔。
- **備份保護**：備份必須加密、限制存取、與正式主機隔離，並以還原演練證明可用。
- **事件處理**：帳號疑似遭用、裝置遺失、資料誤寄或大量下載時，先停用相關存取、保存查修編號與稽核紀錄，再由指定人員判斷通報。
- **弱點治理**：每月檢查套件與映像；重大弱點依風險訂修補時限，不能只靠年度盤點。

## 十二、主要風險與控制

| 風險 | 影響 | 控制 |
|---|---|---|
| 功能很多但沒人會用 | 回到 Excel、資料不完整 | 任務型手冊、情境說明、代表使用者驗收 |
| 所有人權限相同 | 個資與財務資料過度暴露 | 分階段角色權限、下載／查看稽核、MFA |
| 只看副檔名或 MIME | 惡意／損壞檔進入正式儲存 | 統一安全上傳與隔離掃描 |
| 網路不穩重複提交 | 重複訂單／收款 | 處理中狀態、冪等鍵、離線待同步設計 |
| 主檔改動回寫歷史 | 財務結算失真 | 生效版本與訂單快照、不可刪已採用版本 |
| 說明落後 UI | 培訓錯誤 | 手冊列入每次發版 Definition of Done |
| 過度重構 | 回歸與停機 | 小步修改、自動測試、備份與 smoke test |

## 十三、產品治理節奏

- 每週：檢視使用者卡點、錯誤查修編號、未完成草稿與 OCR 失敗。
- 每月：代表使用者 30 分鐘回顧；檢查搜尋速度、磁碟、備份、慢查詢與未對帳。
