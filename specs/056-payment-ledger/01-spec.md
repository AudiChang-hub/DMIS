# 收款帳本與取消退款結算（Phase 1）

批准：使用者 2026-09-29 同意 Phase 1 規劃，帳本方式選 A（擴充 `PaymentRecord`），舊取消單選 A（只標記舊制退款）。
補充規則：未確認的人工收款列可刪除、已確認一律只能沖銷；分期公司已撥款即不能取消。

## 範圍與接受條件

- H1：退款依「已確認淨實收」結算；取消時填沒收金額與原因，應退＝實收－沒收，由系統計算。退款寫入負向 `refund` 紀錄。
  有未確認實收或分期公司已撥款時不能取消；已登記取消不可重複登記。
- H2：已確認收款不可改金額、日期、方式、帳戶、刷卡明細、分類，不可取消確認或刪除；更正以整筆 `reversal` 沖銷後重新登記。
  沖銷／退款列不可修改或刪除（模型防改＋資料庫約束）。取消流程中鎖定訂單內容、折扣與配車，訂金應收不回寫約定訂金；已取消訂單收款唯讀。
- M2：收款摘要顯示客戶／分期溢收與未確認實收；同日同額且未沖銷的已確認收款須勾選「確認非重複收款」並留事件；可登記退還溢收（上限為溢收額）；總表與訂單清單新增「溢收待退」。
- M4：已交付的系統訂單在金額或收款異動後，若產生待補收或溢收，寫入 `settlement_gap` 事件並列為待辦；補收以新增收款、退差以退還溢收處理，不新增訂單狀態。
- 已被沖銷的收款與其沖銷列不列入撥款、刷卡手續費與分期確認。
- 歷史匯入仍可在 `payment_ledger_maintenance()` 受控範圍重建收款。

## 資料變更

Migration `0152_payment_ledger`：`PaymentRecord.entry_type／reverses／adjustment_reason` 與三條約束；
`SalesOrder.forfeited_amount／forfeit_reason／refund_settled_legacy`。資料步驟只把部署當下已取消的訂單標記為舊制退款，
不新增或改動任何金額；舊制訂單沿用原刪除判斷。

## 不在範圍

Phase 2／3（分期核貸閘門、領牌後反向流程、車行額度、狀態機與庫存日誌）；發票與通知。

## 回復

新欄位皆有預設值，可單獨退回 1.18.x 程式而保留 schema；若已產生沖銷／退款列，舊程式會把負數列當收款加總（淨額仍正確）。
Migration 可反向，但僅在尚未產生沖銷／退款列時直接反向。部署前依維運文件備份。
