# 00 — Charter：使用者管理模組（user_management）

## 背景與動機

DMIS 系統部署後，不同角色的使用者（業務、財務、管理員）需要看到不同的選單範圍，
但 Odoo 原生群組機制以「模型存取」為主，缺乏「選單可見度」的精細控制。
本模組提供一層「自訂存取群組」，讓管理員以圖形介面勾選各群組可見的選單，
實現不改動任何現有模組、僅在渲染層動態過濾的目標。

## 目標

1. 提供 `um.access.group` 模型，管理「選單白名單 ↔ 使用者 ↔ 存取群組」三方關聯。
2. 覆寫 `ir.ui.menu._visible_menu_ids()`，依使用者所屬群組的選單聯集動態過濾。
3. 確保管理員（`base.group_system`）與超級使用者不受任何限制。
4. 提供稽核日誌（`um.audit.log`）記錄關鍵操作。
5. 不修改任何 Odoo 核心程式碼或其他模組的安全設定。

## 範圍

| 包含 | 不包含 |
|---|---|
| `um.access.group` CRUD 介面 | 修改 ir.model.access / record rules |
| `res.users` 擴充（um_group_ids） | 頁面層級的 JavaScript 控制 |
| `ir.ui.menu` 覆寫（選單過濾） | 報表或資料的列存取控制 |
| `um.audit.log`（稽核日誌） | 其他模組的選單/視圖修改 |

## 非目標

- 不建立角色繼承階層（使用聯集邏輯）
- 不影響已有的 Odoo 群組指派
- 不提供 API 端點

## 驗收標準摘要

- 指派 um_group 的使用者只能看到白名單選單（及其祖先）
- 未指派 um_group 的使用者行為與原始 Odoo 相同
- 管理員不受限制
- 8 個單元測試全部通過
