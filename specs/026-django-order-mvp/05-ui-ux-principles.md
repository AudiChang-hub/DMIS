# 全站 UI／UX 設計準則

## 設計目標

- **熟悉**：沿用使用者在現代網站、iOS／Android 與企業後台已熟悉的導覽方式。
- **可恢復**：任何頁面都能清楚返回；可能遺失資料的離開動作必須提醒。
- **保留情境**：返回時優先回到上一個站內頁面，保留篩選、搜尋與捲動狀態。
- **跨裝置一致**：資訊架構一致，但桌機使用完整寬度與多欄，手機使用單欄與底部主導覽。
- **清楚回饋**：成功、錯誤、載入與鎖定狀態靠近相關內容；非關鍵提示不阻斷操作。

## 參考準則

- Apple Human Interface Guidelines：Familiarity、Flexibility、Simplicity、Feedback。
- GOV.UK Design System：Back link、Layout、Error summary。
- Material Design 3：頂層 navigation bar 與響應式 layout 原則。

## 導覽規則

- 首頁是最上層，不顯示返回。
- 清單頁返回待辦首頁。
- 詳情頁與新增／編輯頁在內容頂端顯示返回入口。
- 返回優先使用同網域瀏覽紀錄；若不存在則使用明確的固定目的地。
- 手機底部導覽只切換最上層區域，不能取代頁內「儲存」、「建立」、「刪除」等動作。
- 桌機與手機都要顯示目前所在的主要區域。

## 不可破壞功能

任何視覺或導覽重構都必須保留：

- 身分證正面位於姓名、生日、證件號碼旁供人工核對。
- 身分證反面位於戶籍地址旁供人工核對。
- 已上傳照片可預覽、更換與刪除。
- 配件、其他費用、其他文件與其他保險均可新增，也必須可刪除。
- 手機可直接拍照或選擇既有檔案。
- 草稿、自動儲存、編輯鎖定、欄位錯誤提示與各訂單工作頁籤維持可用。

## 驗證基線

- 桌機：`1440×900`
- 平板：`820×1180`
- 手機：`390×844`
- 每次 UI 修改執行 `?ui_audit=1`，必須得到 `data-ui-layout-issues="0"`。
- 自動測試必須驗證關鍵預覽、刪除與動態增減控制仍存在。
