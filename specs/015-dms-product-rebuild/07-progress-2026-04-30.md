# 07 — 進度報告（2026-04-30 價格表重製與資料源統一）

> 延續 `feat/015-dms-product-rebuild` 分支，2026-04-30 處理使用者於價格表（pricelist）反映的資料一致性與重新設計。

## 1. 背景

使用者於價格表點擊 DR-Z4S（越野版）詳細頁，發現「定價與分期」分頁無資料，但產品頁面上是有的。經追查發現系統內存在兩個不同層次的「分期」概念：

| 概念 | 來源欄位 | 性質 |
|---|---|---|
| 自動估算分期金額 | `dms.product.installment_12/18/24/36/48/60_price` | compute = `floor(cash_price/N + 0.6)`，凡有 cash_price 皆有值 |
| 實際分期方案 | `dms.product.installment_line_ids` | 一對多明細（含 finance_company / interest_rate 等），全 41 筆產品中僅 6 筆有 |

這也催生了「直接把產品頁面欄位整理成單一表格」的需求。

## 2. 變更項目

### 2.1 價格表（dms_product）重新設計

| 檔案 | 內容 |
|---|---|
| `addons/dms_product/views/product_template_views.xml` | `view_product_sku_pricelist_tree` 改為 16 欄一字排開：品牌、機種、型式、年份、車色、建議售價、現金價、12/18/24/36/48/60 期金額、顧客贈品、附加費用說明、啟用 |
| 同上 | `editable="bottom" multi_edit="1" default_order="brand_id, template_family_name, production_year desc"` |
| 同上 | 唯讀欄位（品牌、機種、計算分期）加 `force_save="1"` 以容許多選編輯 |
| 同上 | 移除 form view 與 `action_open_form` 按鈕；`action_product_template` 僅保留 tree，並加 `domain=[('active','=',True)]` |

### 2.2 顧客贈品 / 附加費用說明資料源統一

原本「顧客贈品」存在 SKU（`dms.product.gift_note`），但同型號多 SKU 各自儲存導致不一致；同時新需求需把「附加費用說明」加入價格表。

| 檔案 | 內容 |
|---|---|
| `addons/dms_product/models/product_template.py` | 新增 `fees_note = fields.Text(string='附加費用說明')` |
| `addons/dms_product/models/product_compat.py` | `gift_note` / `fees_note` 改為 `fields.Text(related='template_id.note' / 'template_id.fees_note', readonly=False, store=True)`，雙向同步 |
| `addons/dms_product/views/product_template_views.xml` | 產品頁面表單內 `sku_ids` 子表加上 gift_note / fees_note 欄位 |
| `addons/dms_product/migrations/16.0.2.4.0/pre_migrate.py` | ALTER TABLE 新增 `fees_note` 欄位；以 SKU 端歷史值 `DISTINCT ON (template_id) ORDER BY template_id, id` 回填到 template 端 |
| `addons/dms_product/__manifest__.py` | 版本 `16.0.2.3.x` → `16.0.2.4.0` |

### 2.3 維運操作紀錄

- 第一次升級時 manifest 已是 `16.0.2.4.0`，導致 `pre_migrate.py` 後加入也未被觸發；以 `odoo shell` 對 42 筆 `dms.product` 呼叫 `_compute_field_value('gift_note')` / `_compute_field_value('fees_note')` 強制重算，related store 欄位回填完成。
- 唯一資料遺失情境：eReady Fun（template id=712 / 716）原 SKU `gift_note='購車金10000元'`，因 related 改造後 SKU 端被視為計算欄位，原值在第一次 upgrade 過程未先寫進 template 即被覆蓋；事後手動 `UPDATE dms_product_template SET note='購車金10000元' WHERE id=716;` 恢復。

## 3. 驗證

- `bash scripts/smoke_odoo.sh` → OK 303
- DB 抽樣：DR-Z4S / DR-Z4SM / eReady Fun / SUI / Saluto 之 `dms_product.gift_note` 已透過 related 帶出 template.note
- 端到端寫入測試（odoo shell）：於 SKU 端 `sku.fees_note = "TEST..."` 後 `commit()`，template 端同步出現該值；清除 template 端後 SKU 端同步歸 False。確認 related store 雙向皆通。
- `fees_note` 為新欄位，目前 9 筆 template 與 41 筆 SKU 全為空值，待業務方依需要於價格表或產品頁面填寫。

## 4. 後續注意事項

- 任何新增 SKU 的「顧客贈品 / 附加費用說明」欄位修改都會回寫 template，並擴散到同模板所有 SKU，使用者編輯時需理解此行為。
- 如未來要在 SKU 端容許不同贈品/費用說明，應改回獨立欄位並設計 UI 區分。
