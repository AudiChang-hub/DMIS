# 報表設計工具改版（T-164，第一版）

使用者反映「報表設計管理」完全不知道怎麼用。採 A 案：`ReportDefinition` 的 draft／published JSON、`validate_config` 與 migration 都不變，只重做設計頁的版面與流程。分三版發布，本版先處理最常用的兩件事：改條件（T1）、改圖（T2）。

## 本版內容

- **報表頁入口**：admin 在報表標題旁看到「編輯此報表」，連結帶 `?from=` 原報表網址；設計頁返回列回到該報表。`from`／`return_to` 只接受 `/reports/<同一份 pk>/` 開頭的站內路徑，存檔後轉址會保留。閱讀頁除了這顆按鈕不變。
- **頂列**：報表名稱直接編輯、狀態（已發布／有未發布修改／草稿）、開放給、報表中心分組。
- **這份報表只算**：固定範圍以標籤顯示，× 直接移除，「調整條件」開啟對話框。常用條件在前，原 Excel 報表比對條件（`legacy_source`、`model_presence`、原型號文字）收在對話框下方；有設定時自動展開。「用哪個日期統計」放在同一列。
- **圖表設定**：取消「資料／樣式／版面／互動」分頁，改為問句順序：圖表名稱 → 圖表類型 → 要看什麼數字 → 依什麼分 → 再細分 → 排列方式／最多顯示幾項 → 這張圖另外只算 → 進階設定。
- **「依什麼分」選單**：分成「常用」和「沿用原 Excel 報表的分類」兩組，設計器上拿掉「（比對用）」字樣；`legacy_motor_type` 顯示為「車種類別」。選項值與 `DIMENSIONS` 完全相同，閱讀頁的標籤不變。
- **畫布**：拿掉左側欄，圖表切換改到右側「正在設定」。不再自動進入全螢幕。寬度預設「自動」：電腦上至少 1180px（與讀者桌機雙欄一致），畫布夠寬時以 100% 顯示，不夠寬時等比縮小並顯示比例；畫布窄於 700px（手機）直接以實際寬度顯示手機版面。另有寬螢幕 1440、平板 820、手機 390。拿掉縮放選單和重複的「預覽本次設計」按鈕。
- **其他報表設定**：說明、閱讀版型、未領牌、分組內順序、附表、資料字典收在畫布下方。

## 第二版：報表目錄

- **報表設計管理**：改為依 `NAVIGATION_GROUPS` 分組的目錄，順序與報表中心相同（依草稿的 `navigation_group`／`page_order`）。每份顯示縮圖（第一張圖的類型）、圖表數、開放對象、狀態，主要動作是「編輯」，其他動作收在「更多」。
- **拖拉調整分組與順序**：`POST /data/report-design/reorder/`（`report_reorder`，僅 admin，有 CSRF，列入 ROOT_ONLY）。
  - 送出 JSON `{"pages":[{pk, group, version}]}`，必須包含全部報表；清單不符或任一版本不符就回 409，整批不寫入。
  - 只改 `navigation_group` 和 `page_order`，草稿與已發布兩邊同步，不發布草稿中的其他修改，也不改 `published_at`。
  - 每份有變動的報表版本號 +1，並留一筆 `reorder` revision。改完逐份跑 `validate_config`；不通過（例如 per_model 報表移出大數據分析）就整批回滾並回 400。
  - `plan_page_orders` 保留原本已經排對的 `page_order`（最長遞增序列），只替移動的報表在空檔中找新值；空檔不夠或超過 999 時，該組改為 10、20、30…。這樣其他分頁正在編輯的報表不會因版本號變動而被擋。
  - 前端：只從把手拖拉，拖拉時原列留在原位、以影子和插入線標示落點，放開才移動並儲存；也可用鍵盤上下鍵。失敗時回到上次儲存的順序並顯示原因。
- **新增報表先選起點**：「＋ 新增報表」開啟對話框，可選 `starters.py` 的 5 個範本（`report_create?start=<key>`；未知的 key 回到預設範本，不接受任意設定），或複製既有報表（沿用 `report_lifecycle` duplicate）。
- **未歸類型號提醒**：依車種分類草稿計算 `unclassified()` 的筆數，連到報表分類設定。

## 第三版：車種類別設定

- **改名**：「報表分類設定」改為「車種類別設定」，涵蓋選單、資料維護區卡片、首頁快速前往、頁面與文案分類。網址、route 名稱、權限鍵和 `ReportClassification.verbose_name` 都不變（改 verbose_name 會產生 migration）。
- **頁面順序**：狀態列（草稿有變更時才出現「檢查影響並發布」）→ 待歸類型號（主要任務：整列點選、表頭全選、已選數量、固定的歸入列）→ 收合的「類別」「型號規則」「版本與還原」（編輯中、驗證失敗或搜尋規則時自動展開）。
- **試算與發布合一**：按鈕名稱改為「檢查影響並發布」，沿用原本的 preview → publish token 流程。結果改在對話框顯示，沒有 JavaScript 時以一般區塊顯示。發布規則與確認勾選都不變。
- **修正按鈕版面**：`_form_fields` 本身已是兩欄格線，舊版又包在兩欄的 `.classification-editor` 裡，操作列被撐成整欄高度，「清空表單」變成圓形、「儲存」變成高長方塊。改為單欄，操作列靠右。同時移除覆蓋 `.button` 外觀的 `.classification-workspace button` 規則。
- **設計器連結**：「依什麼分」或「再細分」選到車種類別時，顯示前往車種類別設定的提示。
