# 共用新增訂單與內部接單

## 已確認與範圍

店內與合作車行共用同一路由、表單及訂單，不建立另一套申請單。選車／車色在前；車主證件、付款與汰舊需求共用。店內財務依權限開放，車行不能修改內部財務。新單先待接單，內部接單後才待配車；顯示接單人與時間，首頁提供待接單入口。店內可明確勾選「由我接單」。接單不可產生重複訂單。

## 實作與安全

- 新增待接單狀態、建立帳號與接單稽核；既有訂單不回填為待接單，保留歷史資料。
- admin 為馭盛店內管理帳號；所屬通路與角色分開，不改成合作車行。初始化只補缺少的設定，不覆寫既有綁定。
- 財務編輯為獨立畫面權限；未取得者可依原權限接單、建立基礎訂單，但完整訂單編輯及財務作業表單為唯讀。
- admin 可設定帳號所屬車行；未綁定者沿用店內帳號。車行帳號採明列功能白名單、資料列／證件／草稿範圍檢查，不依靠隱藏選單。既有帳號不自動改綁。
- 財務欄位後端驗證；車行來源不可偽造，分期依現有車型有效方案核對。共用主檔，不複製售價、分期維護頁。
- 接單為 CSRF 保護的 POST，以 transaction 與 row lock 防止重複接單；接單前不可配車。保留既有取消、退款、領牌、交付及淨利公式。
- 車行送出後以唯讀訂單進度查詢；修正由店內既有編輯流程處理，避免已受理內容被無聲覆寫。
- 補上汰舊意向（是／否／待確認）、下訂補充與分期附件；意向不等於正式申請補助。證件仍沿用 OCR／人工核對與受保護媒體。
- Google Sites／Forms 本次不變更、不送出；共用系統先以車款與車色選擇提供入口，可由合法車型／車色連結預填，不信任 URL 文字或金額。

## 驗收與發布

新單待接、店內自接、兩人競爭接單、重送、舊單相容、未接不得配車、首頁與篩選、跨車行讀寫／附件／API／草稿及 WebSocket、偽造來源及金額、分期主檔、財務權限、資料完整性均補測。桌面／手機共用流程真實瀏覽器驗收。本次相容功能新增預定 1.2.0；完整 SQLite／PostgreSQL CI、備份、tag、部署、健康與正式功能驗證後才算交付。

回復以保留新欄位／附件資料為原則；已產生待接單後不可直接回退到不識別此狀態的舊程式，須先處理待接單或發布前向修正。
